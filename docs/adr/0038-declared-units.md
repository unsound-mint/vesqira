# ADR 0038: A unit the researcher declares for a file that has none

Status: **accepted** (owner direction of 2026-11-05: unknowns go to one list and are never guessed; the Projects "needs your input" page, ADR 0030). Implemented.

## Context
Many FITS files have no `BUNIT` card (the VGT maps, derived products, anything written by a tool that does not set it). The header facts the worker reads say `bunit: null`, `bunit_status: "unresolved"`, and every readout, figure and comparison says "brightness unit unresolved". The Projects "needs your input" page asked for the unit and stored the answer, but only in the project's answers: no viewer, figure or board ever saw it, so answering changed nothing a researcher could see. AGENTS.md rules out inventing a unit and rules out editing the original; the researcher, though, does know what the unit is, and `docs/product/shape.md` (Q143) wants such knowledge kept as a layer with attribution and history, never as an edit of the file.

## Decision
- **A declared unit is an overlay.** `dataset_units` holds one row per dataset: the unit exactly as typed, who declared it (`user`), when, and the file's size and modification time at that moment. The file and the header facts the worker read are never changed; `header.bunit` and `header.bunit_status` stay what the file said. A declaration is stale when the registered file differs from what it was (shown, not hidden).
- **The file always wins.** A file whose header states a unit (a `BUNIT` card, or a `bunit` value) cannot be given a declaration (409), and a declaration made while it had none is dropped when the file is read again with one. Overriding what a file says is a correction, a different and larger decision (Q143), and is not built.
- **Only a brightness.** An orientation map (proposed by a run import or confirmed) and the reliability map declared for one have angles and a dimensionless reliability, not a brightness: they are refused (409), are never asked about in the Needs list, and the inspector says why.
- **A stale declaration is not applied.** If the file changed since it was declared (size or modification time), the declaration is shown as stale, is not sent to the worker, is not accepted for a figure's limits and does not settle a Needs question; "It still applies" confirms it for the file as it is, or it can be withdrawn.
- **One source for the viewer.** The server passes the declaration to the worker with each request for that dataset (`declared_bunit`), and it is part of the plane cache key. The worker, which already builds every head's `bunit` from the header, answers with `bunit_status: "user"` (new, next to `declared`, the file's, and `unresolved`) when it used it. The server's cached replies cannot carry a stale unit, and view, plane, spectrum and coordinate heads agree. The browser keeps the heads it already holds, so the viewer reads its layout again when the declaration changes (the plane and spectrum follow; the channel and region stay).
- **Said wherever it is shown.** The inspector writes "Jy/beam (declared by you, not in the file)", the readout footnote, the display controls, the spectrum plot and the compare inspector say it, the caption of a saved figure (the PNG, which travels without its provenance) says "Brightness unit (…) declared by the author; the file has no BUNIT", and a figure's provenance (which the reviewer sees) gets `unitDeclaration` and the statement "The brightness unit (…) was declared by the author of this board, not by the file: the file has no BUNIT." A figure's limits can be in the declared unit; any other unit is still refused.
- **What counts as a unit.** 1 to 40 characters of letters, numbers (so `m²` is fine), a single blank between words and `/ * ^ . + - ( ) _ , % · °`; no leading or trailing blank, no markup, quotes or backslashes (the text reaches provenance, PNG metadata and the reviewer's page). It is not parsed or converted and is not checked against a unit vocabulary: it is kept and compared as text, so `Jy/beam` and `Jy beam-1` are two different strings.
- **Where it is set.** From the dataset (inspector section "Unit of the values", withdraw included), and by answering the Needs question, which applies it to the files the question lists, all or none in one transaction. A file declared on its own leaves the open list. An answer "declare V" holds only for the files that really have V: when one file gets another unit or loses it, the question reopens for exactly those files, and answering again moves them and the files that still had the old folder unit, so the recorded answer never claims more than the files show. A question left "unknown" stays answered and the health checklist says it was left unknown, not that units are declared. Every declaration that was applied, and every withdrawal, is audited.
- **Filters** (`unit:Jy/beam`, `unit:none`, the autocomplete) use the file's unit, else the declared one.

## Alternatives
- **Write the unit into the file's BUNIT.** Rejected: an original is never altered (AGENTS invariant 8), and the file would then claim to have said it.
- **Patch `bunit` in the header facts the catalog stores.** Rejected: the header would stop being "what the file declared", and the declared unit would be indistinguishable from the file's. The overlay keeps the two apart.
- **Overlay the unit in the browser or after the worker's reply.** Rejected: the plane format is binary with a JSON head, and each consumer would need patching; one input to the worker is a single place.
- **Parse and canonicalise the unit with astropy.** Deferred: it would catch typos and allow conversions, but it adds a worker round trip and rejects non-standard units researchers do use. The unit is text for now.

## Consequences
- Declared units reach views, figures (captions and provenance), boards, reviewer provenance, filters and the Needs/health pages. They do **not** yet reach analysis products: moments, difference maps and other derived files still read the file's `BUNIT` and say "unresolved" for a file that has only a declaration (conservative, and inconsistent with what the viewer shows), and a scalar difference between two files still requires the files' own units to agree.
- Schema version 4 (`internal/schema`, migration "declared units", snapshot `testdata/schema_v4.sql`): one new table that cascades with its dataset. An upgrade copies the catalog aside first, like every schema change; `GET /api/datasets` and `/{id}` gain `unitDeclaration`; the view head's `bunit_status` gains `user`; one new route, `POST /api/datasets/{id}/unit` (`{unit}` or `{clear: true}`). Contract and generated web types are updated.
- An older web client reading a newer server sees an unknown `bunit_status` value; no old client reads `unitDeclaration`. An older server refuses a version 4 catalog ("newer than this program"): see Rollback.

## Validation
`schema/declaredunits_test.go` (a schema 3 catalog upgrades with every dataset kept, the table cascades, a backup is made first) and the catalog snapshot test; `catalog/unit_test.go` (overlay never touches the header, either-field rule, text rules, staleness, cascade); `server/units_test.go` (real worker, on a scalar cube with its BUNIT card removed: view, plane, coordinate and spectrum heads all say the unit as `user`, withdrawing restores `unresolved`, 409 for a file with its own unit and for an orientation map, the file's bytes unchanged; and with a fake worker that echoes what it is sent: the unit is sent only when current, each state is answered from its own cache entry, a stale declaration is not sent); `projects_test.go` (an answer reaches the datasets, withdrawing one reopens the question, a settled folder stops asking); `boards_test.go` (a figure of a declared-unit map saves, also with a 35-character unit, its provenance and the reviewer page say it is the author's, a stale declaration is refused); `test_plane_worker.py` (fills a gap, never overrides the file's unit, refuses malformed text); web tests for the control, the wording, the figure caption and the viewer refetch (each fails when its code is removed); `e2e/tests/z-projects.spec.ts` (declare on the Needs page, see it in the inspector, the viewer following without a reload, axe, withdraw, declare again, no control for a file with a unit). Not tested: the pixels of a saved figure's legend (only its caption lines), and an old project whose earlier answer predates this change reopens its question without saying why.

## Rollback / Migration
Upgrading a catalog creates `dataset_units` and stamps schema 4, after copying the catalog to `<db>.before-schema-4-<time>` (mode 0600). An older build refuses a version 4 catalog rather than half-understanding it, so going back means restoring that copy (declarations made since are lost), or dropping the table and setting `PRAGMA user_version = 3` by hand. Either way views say "unresolved" again for those files, which is what the files themselves say.
