# ADR 0063: Virtual subsets, a definition that is materialised on demand

- Status: proposed; implemented, awaiting owner review.
- Date: 2026-11-12
- Builds the Stage 5 item "Virtual subsets (a definition, not only a materialized cutout)" (Q141; `docs/product/shape.md` §5: "a saved subset is a virtual versioned dataset (source version, region, spectral interval) materialised on demand; existing scripts must run unmodified on resolved or materialised files; v1 is ordinary file compatibility plus reliable materialisation"). Reuses the cutout and slab path of `services/scientific-worker/analysis.py`, the dataset identity of ADR 0053, derived records (ADR 0041's impact preview and the `derived` table), the corrections of ADR 0061 and the saved regions of the viewer. The schema is 24 (corrections took 23); expect renumbering at merge if another branch took 24.

## Context

A cutout today is a file: the researcher picks a box, waits for the analysis program, and gets a new cube that duplicates bytes, has its own identity and is already out of date when the source is read again. What they mean is "this part of that cube": a window. Working on a window needs no copy (the viewer reads planes and spectra selectively anyway), but a script, a collaborator or a supervisor's laptop needs a real file. Q141 asks for both: the definition is the thing, the file is made when something needs it, and the file must be ordinary.

## Decision

**A subset is a definition, never a file.** It names a source dataset and a window onto it:
- a spatial **box** in the source's 0-based pixels (inclusive), given directly or taken from a saved region's bounding box (a circle's square, clipped to the image; a line has none; the region's id and name are kept as where the box came from, the box is a copy);
- an optional spatial **step** (1 to 64): every step-th pixel of the box, values untouched (strided sampling, never an average, so it is valid for an orientation map too);
- a spectral **interval**: a channel range, or a world interval stored with its unit and frame and resolved to channels (below). No interval means every channel;
- a **name** (1 to 80 characters of plain text) and a **reason** (required, 500), the same text rules as a correction.

It is **mutable working state** (AGENTS.md lifecycle) with an append-only history: `subsets` (identity, source) and `subset_versions` (name, reason, definition JSON, kind create/edit/repin, who, when, and the **identity of the source file the version was pinned to**: registered size, modification time and recorded content identity, compared with `catalog.Changed`, the rule corrections use). Rows are never updated (a trigger refuses it). An edit is a new version; a file written from a version keeps the version it was written from.

**Viewing needs no materialisation.** `GET /api/subsets/{sid}/view | plane | coord | spectrum | header-cards` are the dataset routes with the window resolved in one place (`planes.go` `sourceWith`, `ask`): the source file is authorised as always, the window goes in the cache key and in the worker request, and the worker reads through it. `Cube` takes the window (`services/scientific-worker/subset.py`): the shape, channel count, header and WCS become the subset's; `_index` is the one place that maps a subset slice to the source's (offset, and a stride for a step), so a plane, a spectrum or a coordinate reads only the window (the test records the slices requested). Coordinates are in the subset's own pixel frame with a WCS that gives the source's world coordinates exactly:
- `CRPIX' = (CRPIX - 1 - first)/step + 1` on the image axes, `CRPIX - first` on the channel axis;
- the step multiplies the image-axis **columns** of `CD`, or of `PC` when the header has one, and `CDELT` only when it has neither. Scaling `CDELT` alone would break a rotated or skewed matrix, and a CD header ignores CDELT altogether (the rotated fixtures and a CD variant test this against astropy on the source);
- the corrections in force (ADR 0061) are part of the header the window is cut from, so a subset of a corrected dataset reads, and is written, with them.

**The worker's echo is checked, like the corrections' hash.** Every reply that read through a window carries `window` (what it resolved to, in the source's pixels and channels); `ask` refuses a reply without it or with another origin, step, size or channel range (502: a worker on a host that ignored the window would otherwise answer for the whole file). Operations that do not read through the window (convert, channel maps, position-velocity, overlays, link, region histogram) are not registered for a subset, and the worker refuses `window` on any operation outside view, plane, coordinate, spectrum and header. Masks are not applied to a subset (409): a mask is in the source's pixels and would have to be cut the same way (not built). Offline copies are neither kept nor served for a window (the store keys files): not when the file is unreachable, and not when the worker on a host fails and the cached copy of the source would otherwise answer.

**A world interval resolves in the worker, by a stated rule.** A channel is in when its **centre**, from the WCS as read (corrections included), lies in the closed interval, compared to a millionth of a channel width so a bound written at a centre includes it. The unit must convert to the axis' own unit **without a spectral convention** (km/s to m/s, MHz to Hz: yes; a velocity to a frequency: refused, because no convention is assumed). A frame must be the one the file declares in SPECSYS; if the file declares none, a stated frame is refused. **No frame is converted or assumed.** An axis that is not fully declared, an interval with no centre in it, or a non-monotonic axis is refused with the reason. Descending axes work. The resolution is repeated on every read (it depends on the corrections in force), the answer is in `window.channel_rule` and `window.world`, and a written file records the channels it got.

**A source that changed makes the subset stale.** Stale means the registered file differs from the pinned one (size, modification time, or a recorded content identity of the same kind that differs). A stale subset is **not shown as current**: the list marks it with the sentence, and view, plane, coordinate, spectrum, header and materialise answer 409 with code `subset_stale`. "Re-pin to the current file" records a new version (kind `repin`, with a required reason) after the worker has checked the window against the changed file; a window that no longer fits is refused with the reason and the subset stays stale. This is the same stance as stale corrections and declarations.

**Materialise on demand.** `POST /api/subsets/{sid}/materialise` writes the current version through the analysis program's `subset` operation (`op_subset`: the same `Cube` window, the planes read one channel at a time like cutout and slab, written by `_write_cube` and `write_fits`), registers the file and records a derived dataset: op `subset`, the source as its source, `params` with the subset's **name, version, reason and definition** and the source identity (what a reviewer may see: no ids or paths), and in the owner-only summary the subset id, version and the reuse key. The FITS header carries the shifted (and step-scaled) WCS with the corrections applied (`VESQWCSC` and HISTORY naming the corrected keywords), BUNIT (a declared or corrected unit is stamped as the researcher's, `VESQBUNS`), and HISTORY lines naming the subset, its version, the source and its identity and the window in the source's pixels. The result is a normal dataset: a script reads it unmodified, and the viewer reads it like any other. Images (2D) are written as 2D; a cube must have axes (x, y, channel) in that order to be written (it can still be viewed, whatever the order). A subset of a map declared as an axial orientation map is written with the same declaration (unit, frame, quantity), said by the operation and not by the researcher, because a window keeps source pixels and turns no angle; its reliability map is another file and is not carried; a declaration made for an earlier version of the file refuses the write (as it does for an analysis).

**Reuse is by key.** Asking again for the same subset, version and source bytes (size, modification time, recorded identity) **and the same corrections in force and declared unit** returns the existing dataset (200, `reused: true`) when its file is still the registered one (`authorize` passes); a changed file or a changed correction makes a new file. One writer at a time, so two identical requests make one file.

**The delete and the corrections previews say it.** Deleting a source lists its subsets (effect "removed": a subset is a window onto its source and means nothing without it) and its materialised files under "derived" ("stays"); files written from a subset are ordinary datasets and stay. Deleting a subset forgets the definition and history; nothing else. A correction preview lists the subsets as "live" (read again with the new values; files already written keep theirs).

**The explorer** lists a subset under its source with a "virtual" mark and the stale mark; it is never drawn like a file, and its panel states that it is a window, not a file, with the form (create, edit), re-pin and "Write as a file". Selecting it opens it in the plane viewer, which reads through `/api/subsets/{sid}` (the viewer gives a subset the negative of its id, which no dataset has, so the one plane client serves both). The inspector says "virtual subset of <source> · version N · box … · channels …", the resolved geometry, the re-pin, write-as-a-file, edit and history. A stale subset shows the 409 sentence and the re-pin instead of pixels. Masks, saved regions, conversions, orientation statistics, a paired reliability map, overlays, channel maps, position-velocity, the exploration history, figures, analyses and compare are not offered on a subset, with one sentence saying why; a region drawn on it is for that view only, and its spectrum comes from the subset route.

## Where this differs from the request, and why

- **Two tables, not one.** The decision says "its own small table"; the history needs an append-only version row beside a mutable identity, so `subsets` holds the identity and `subset_versions` the versions. Both are small.
- **Step scales the matrix, not CDELT alone.** The request says "CDELT scaled for a step". For a header with `CDELT` and no matrix that is exactly what happens; for `PC` or `CD` headers the matrix columns are scaled, because that is what keeps rotated fixtures exact.
- **The world interval is resolved at read time, not stored as channels.** Corrections change the spectral axis, so a stored channel range could silently disagree with the file as read. The version stores the interval; every reply and every written file states the channels it resolved to.

## Alternatives

- **A subset as a row of `datasets` with kind "subset".** The viewer would open it unchanged, but every code path that assumes a path, a size and a registered file (change detection, identity, transfers, offline, jobs, scans, delete) would meet a dataset that is not a file. Rejected: "never confused with a file" is a property of the model, not of a badge.
- **Resolve in the API.** Rejected: the API does not read WCS (ADR 0042 §4); one worker keeps every readout consistent with the materialised file.
- **Materialise by chaining the existing cutout and slab operations.** Two files and two provenance records for one subset, and a step the cutout does not have. One operation with one window.
- **Block-mean for the step.** Invents values and breaks axial maps. Strided sampling keeps every value a source value.
- **Always materialise.** What the researcher did before: a copy per question.

## Consequences

- **Follow-up: a typed viewer source.** The viewer tells a subset from a dataset by the sign of its id (`isVirtualId` in `api/planes.ts`). It is confined to the plane client and the shell, and every panel that would read by dataset id is hidden on a subset, but a `{kind, id}` source threaded through the viewer would make the distinction a type rather than a convention; do it when a second virtual kind (a composite) arrives.
- A subset costs one small row per version; reading it costs what reading the source window costs (the strided read touches the pages of the window).
- Not built: the viewer's other tools on a subset (they need their routes made window-aware one by one), masks and saved regions on a subset, overlays and channel maps of a subset, subsets of a point catalog, subsets of a cube with the channel axis first, a subset of a subset, a spectral reference-frame transform, materialising on a host (a file on a host is viewed here, written there as a cutout job), subsets in boards, figures and reviews (a figure of a subset pins the source today), and a subset collection.
- A subset of a file whose rows change keeps being a window onto "the file as pinned": a changed source is detected by size, time and recorded identity, not by content, so a file replaced by one of the same size and time with no recorded identity is not noticed (the same limit as corrections).

## Validation

- `services/scientific-worker/test_subset.py`, three oracles (numpy slicing of the source, astropy on the source's own header, a materialised file read as an ordinary file): box, channel range and step 2 on the plain, PC-rotated, CD-matrix, reverse-spectral and frequency fixtures give planes bit for bit, world coordinates to 1e-9 and region spectra byte for byte equal to the materialised file's; a step that does not divide the box; the PC and CD columns scaled and CDELT left alone; the reference pixel moves; world intervals resolve to the channels astropy says (km/s, m/s, MHz, a descending axis, a bound at a channel centre) and are refused for a wrong frame, a velocity-for-frequency unit, an empty interval, an undeclared axis; the slices requested of the file stay inside the window and never cover a whole plane; a window onto a plane over the viewer's limit works; the same world interval selects other channels under a spectral correction; flags renumber; a 2D image is written as 2D; operations that cannot read through a window are refused; corrections, BUNIT and HISTORY reach the file; the input is not modified.
- `services/api/internal/server/subsets_test.go` (real worker): create with every refusal and the stored geometry; view, plane, coordinate, spectrum and header equal those of the materialised dataset on three fixtures; stale after a changed file (every route 409), re-pin refusals and success, a new version makes a new file and the old keeps its version; reuse and non-reuse (changed file, new correction), the corrections in the header and the derived record; impact lists the subsets and the written file, delete removes subsets and keeps the file; routes that cannot be windowed are absent and masks are refused; a worker that ignores the window is refused (502); the echo check. `subsets_offline_test.go` (a copy of the file is served for the file but never for a window when the host's worker fails); the record of a file written from a region's box names the region, not its id; a file written from an orientation subset is declared as one and is not averaged. `internal/subsets`, `internal/schema/subsets_test.go` (a schema 23 catalog upgrades, versions cannot be edited), `TestCatalogSchemaSnapshot` with `testdata/schema_v24.sql`, the lifecycle guard.
- Web: the subset form, the explorer marking (virtual, stale), re-pin and write-as-a-file calls, the inspector line; `viewer/virtualSubset.test.tsx` (the viewer reads view, plane, coordinate and spectrum through the subset's routes and makes no other request). `e2e/tests/zzzzzzzz-subsets.spec.ts`: create from the dataset inspector, browse it in the viewer (9 by 7 pixels, the inspector line, no tabs or tools that need the file), see it under its source marked virtual, check the coordinate readout of its first pixel against the source's own coordinate at the offset pixel, axe, write it as a file and find the dataset.
- Not verified: a subset read through a host's worker (the echo check is the guard; no host in the tests), strided reads of a file that cannot be memory-mapped (compressed: the section reader serves them, untested here), the narrow and compact laptop sizes and light mode beyond one screenshot, and timings of a strided read on a large cube.

## Rollback / Migration

Upgrading creates `subsets` and `subset_versions` (with their index and trigger) and stamps schema 24 after the usual copy to `<db>.before-schema-24-<time>`. An older build refuses a version 23 catalog; going back means restoring that copy (subsets made since are lost; files written from them are ordinary datasets and stay) or dropping the two tables and setting `PRAGMA user_version = 23` by hand, after which the explorer shows no virtual datasets. No file was ever changed.
