# ADR 0054: Run environment and rerun modes

Status: **proposed; implemented, awaiting owner review.** Decided by the implementing agent under the owner's delegation of ADR decisions (roadmap Stage 4; Q121 to Q125, Q198, Q123, Q246). Real Slurm and a real cluster are not verified (see Validation). The new run-page blocks, the rerun mode choice and the draft check have had no approved design direction and no visual review.

## Context
The run page's "what is known about rerunning this" listed the code version as declared (from the pipeline's own metadata) and the software environment as unresolved: nothing recorded Julia, packages, modules, the machine or the input file's state, and nothing could say whether a rerun ran the same code. "Run again with…" repeated the settings only. Controls (smoothing, noise model, how a null was built) were free text in a run's parameters at best. AGENTS.md requires provenance to be labelled `verified`, `declared`, `inferred` or `unresolved`, forbids claiming an RNG, a calibration or a reference table that was not established, and forbids any change to the researcher's repositories.

## Decision
- **The job observes; Vesqira reads.** Every VGT and ROHSA job script gets a preamble (`jobs.EnvPreamble`, inserted just before the program starts, so for ROHSA after the module and build lines) that runs read-only commands and writes `vesqira-env.json`. It is written first in the job's own directory (`$SLURM_SUBMIT_DIR`) and copied next to the outputs when the output folder exists, and again on exit (the pipeline may create its folder only after it starts). It runs in a subshell with `set +e +u` and `|| true`: a missing `git`, `module` or `julia` never fails the job. Facts: code commit, tracked-files-changed flag, a hash of `git diff HEAD` (tracked files; `none` when clean), the number of untracked files (counted, not treated as dirt: the templates put `JULIA_DEPOT_PATH` inside the code folder), `julia --version`, the sha256 of `Manifest.toml` in the code folder (not `Pkg.status`, which is expensive), the `module list` text (200 characters) and its hash, the node name, the CPU model, the input file's size and modification time, and the Slurm job id. Python is reported unresolved with the reason "the job template does not run Python": no template runs it, and recording an interpreter the job never used would be a claim.
- **Read-only, mechanically.** Git runs only as `git --no-optional-locks -C <dir> rev-parse|status|diff` (`diff` with `--no-ext-diff --no-textconv`, so a configured driver cannot run a program), so not even the index is refreshed. No commit, stash, fetch, checkout or config change. `TestPreambleOnlyReadsTheCodeFolder` greps the template for every write-capable subcommand and requires every git call to be one of the three forms; `TestPreambleRecordsVerifiedFactsAndLeavesTheCheckoutAlone` runs it against a real checkout with an untracked file and compares `.git/index` byte for byte and by mtime. Paths reach the script only if they pass `ValidPath`; an input path that does not (relative, spaces, quotes) is left out and the fact is unresolved with that reason. Every printed value is cut to a fixed character set and 200 characters, so the file is bounded (under 6 kB; tested with a 300 kB module list).
- **Verified means observed by the job itself.** `runs.ParseEnv` treats the file as untrusted: at most 16 kB, only the known keys, each value checked against its own pattern (a bad value becomes unresolved with a fixed reason), and the file counts only for the Slurm job it names: its `slurm_job_id` must equal the job's `slurm_id`, otherwise every fact is unresolved ("written by another job"). A fact the job could not read says why. The file is not signed: the label says "observed by the job itself when it ran, from a file next to its outputs (not signed)". Declared facts stay declared: the pipeline's own `gitcommit` is kept beside the verified commit, and a disagreement is shown in the code fact.
- **Where it lands.** When a VGT or ROHSA job's results are imported (the button, the automatic import, or a ROHSA fit), the API reads the file through `hosts.Manager.ReadExisting` (no new write path: this ADR adds none) and stores the facts on the run (`runs.environment`, JSON, schema 16). No file next to the outputs, a link, or a file from another job gives all-unresolved with that reason; an unreachable host leaves an earlier record as it was. At the job's end the same facts are merged into the rewritten `run.json` (`vesqira.environment`, with a provenance sentence); `run.json` stays a record Vesqira writes through `WriteFile` (ADR 0039) and the facts in it are not read back by discovery.
- **The input by content (ADR 0053).** The job still observes only the input's size and modification time. The sampled fingerprint (`sampled/1`, not a hash of the whole file) is added by the API at import as `input.sampled_fp`: taken from the dataset's own location record when it has one for that size and time, otherwise measured by the host's worker, and kept only if the file's size and time still equal what the job observed; otherwise it is unresolved with the reason. It is therefore a measurement made at import, evidence about the bytes the job read, not an observation by the job (the job cannot run the worker: it is a shell fragment on a compute node and the worker's path is not known to it); its label says so. A strict rerun compares the input by this fingerprint when the parent has one and the host can measure it now (an equal value does not block when only the modification time differs; a different value blocks even if size and time agree); otherwise size and modification time decide and the check says that it fell back.
- **Rerun modes.** "Run again with…" gets a choice stored with the draft (in its request, so no jobs column): **adapted** (the default and the earlier behaviour; the settings that differ from the parent job are marked, by `settingsChanges` on the effective settings, config text plus overrides), **best effort** (the code as it is when submitted; every difference from what the parent observed is listed before submitting and noted in the audit line) and **strict**. Strict means the parent's verified commit with no changed tracked file, the same Manifest.toml and the same input file size and mtime. It is possible only when the parent's commit is known and clean (observed, or declared in full and not `-dirty`); the draft is refused with the reason otherwise, and also when its settings differ from the parent's (change settings in adapted). Before submitting, `submitDraft` reads the code folder on the host with the same collector (`jobs.EnvProbe`, a fixed `bash -s` command, the script on stdin, paths validated) and refuses with `409` and the list of differences if the revision differs or cannot be read, tracked files have changed, or Manifest.toml or the input file differ; nothing is recorded or sent. The strict script also embeds the expected revision and stops itself (exit 3) if the folder moved while the job queued. Julia version, modules, node and CPU can only be seen on the compute node: they are compared on the run page afterwards, and the UI says so. `GET /api/jobs/{id}/rerun-check` returns the same comparison for the screen (read-only).
- **The run page for a rerun** shows, from the two runs' own observations, each compared fact as matched (both verified and equal), differed, or not comparable (a side did not observe it, never reported as matched), with which differences a strict rerun requires to match. The mode is shown. The list route leaves the comparison out; the single-run route has it.
- **Controls (Q246).** Optional structured blocks on a run, `PUT /api/runs/{id}/controls`: smoothing (kernel, width, and the unit of the width from a fixed list; a width without a unit, or a unit without a width, is refused), noise model (scalar sigma with its unit, rms map, per-channel rms, other; how it was estimated, in words) and how a control or null was constructed (shifted-map null, injection test, permutation, other; up to 12 named parameters). Each block is stored as declared by the researcher with the time, whatever the request says (`Controls.Declare`); a block left off is cleared; not stated is not "none applied". They appear on the run page, and travel with the run to a reviewer (`RunSummary.controls`, optional, absent in snapshots frozen earlier, shown in the reviewer's run line).
- **Relative orientation fills its null by itself.** The derived record of a relative-orientation result (ADR 0047) gets `params.controls.construction` built from the worker's own summary (method text, `n_shifts`, `min_shift_deg`, `keep_fraction`, `seed`, shifts kept), labelled verified by Vesqira because Vesqira ran it. It is not written when the null did not run (`null.skipped`) or the summary does not say. The map null is a `shifted_map_null`; the catalog null moves the source pattern over the map, so it is recorded as `other` with the worker's method text. No claim about the random generator beyond the recorded seed is made.

## Alternatives
- **Read `Pkg.status` or `pip freeze`:** slow on a login node and writes caches; a Manifest.toml hash identifies the resolved set cheaply. Python is not run by the templates, so no hash of it is recorded.
- **Capture on the login node at submission:** the compute node's modules, Julia and CPU are what matter, and they differ. Only the code folder, the Manifest and the input are checked before submitting.
- **Run `git status` plainly:** refreshes `.git/index`, a write to the research repository. Rejected.
- **A sampled content fingerprint of the input:** the dataset-identity work that defines one is not on this branch; size and modification time are recorded and labelled as exactly that. Switch to the shared definition when it lands.
- **A jobs column for the mode:** the mode is part of what the draft was asked to do, and the request JSON already holds that.
- **Write the environment into run.json only:** the run page needs it on the run, for comparison, even when run.json could not be written.

## Consequences
- Schema 16 (`runs.environment`, `runs.controls`, both `TEXT NOT NULL DEFAULT ''`; every existing run gets "not observed" and "not stated"); an older build refuses it (ADR 0020). `testdata/schema_v16.sql` is the snapshot. No lifecycle change: the columns hold no references to catalog entries.
- Job scripts grow by about 5 kB; a script submitted before this change has no preamble and its runs show all-unresolved environments.
- The preamble runs `julia --version` (a short start) on the compute node. Sweep reviews classify the preamble's copy of the output folder (`ve_out=`) as the output folder, like `output_dir`.
- Facts are observed, not proved: someone with write access to the output folder can edit the file. The label says so.
- Contracts: `GET /api/jobs/{id}/rerun-check` and `PUT /api/runs/{id}/controls` are described; `RunSummary.controls` is optional; the run routes remain undescribed (the list did not grow).

## Validation
Go: `jobs/env_test.go` (read-only text and effect on a real checkout, facts and unresolved reasons, hostile input path, bounded size, strict guard stopping the job, copy on exit, probe), `runs/env_test.go` (parsing with labels, another job's file, malformed values, comparison never matching an unobserved fact, reproducibility labels), `schema/runenv_test.go` (migration) and the snapshot tests, `server/rerunmode_test.go` (environment kept and merged into run.json, foreign or absent file, strict refused on a dirty or moved folder with nothing sent and the draft left a draft, best effort submitted with the differences in the audit, strict draft preconditions, adapted marking changes without a host call, run comparison with its parent, contract checks), `server/runcontrols_test.go` (declared as the researcher whatever is sent, refusals, carried to the reviewer's summary, contract), `server/relorient_test.go` (verified construction when the null ran, none when skipped). Web: `runs/envcontrols.test.tsx` (control text, form refusals, reviewer run line, comparison table, mode choice with strict refusals, draft check, run page). **Not verified:** a real cluster (login-shell banners, Lmod `module list` formats, BusyBox or BSD `stat`/`hostname`, a pipeline that creates its output folder late, `julia` on the compute node's PATH), the strict check against a code folder on a shared filesystem the login node sees differently, and any visual review of the new blocks.

## Rollback / Migration
Remove `EnvPreamble` from the two renderers and the `linkJobRun` read to stop capturing; the columns and files already written stay and are inert. A catalog at schema 16 is refused by an older build (restore the copy the upgrade made, ADR 0020). Delete `vesqira-env.json` on a host at any time; the run then shows the facts as unresolved.
