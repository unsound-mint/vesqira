# ADR 0042: One scene model for overlays, linked views and figures; declared angle conventions

- Status: proposed; awaiting owner review (decided by the developer while the owner had delegated ADR decisions, 2026-11-11)
- Date: 2026-11-11
- Related: ADR 0005 (workbench), 0017 (comparison), 0026 (regions), 0027 (histogram, zoom, shared scale), 0034 (GPU renderer), roadmap Stage 3 (linked views), Stage 6 (figures as specifications), Stage S (this ADR)

## Context
Three roadmap items are the same design seen from different sides:
- an overlay drawn from another dataset (CO contours on H I, VGT segments on intensity, star polarization vectors);
- linked views that follow each other by sky position and velocity instead of by pixel index (Stage 3, Q174);
- a figure stored as a specification that can be drawn again and exported as SVG (Stage 6, Q186).

Today a viewer pane draws one dataset with its own display settings. Orientation lines are drawn only on the orientation map itself. Two panes link only when the server confirms an identical grid. A figure is a PNG plus provenance.

Orientation data has a semantic gap that blocks every cross-dataset comparison:
- The catalog records only that a map is axial and in degrees or radians. It does not record the reference direction or what the angle means.
- The VGT pipeline writes ψ in radians in the pixel frame, counter-clockwise from FITS axis 1, already rotated 90° from the gradient so that it is a B-field proxy. The file carries no header key saying so.
- Starlight polarization catalogs give a position angle east of north (IAU) that is parallel to B.
- Planck 353 GHz gives Q/U in the COSMO convention, so U must change sign for IAU, and the dust polarization angle is perpendicular to B.

Comparing any two of these without converting both to the same quantity in the same frame produces a wrong answer that looks plausible.

Shipped code also resamples axial maps like scalars. `align` (reproject_interp or reproject_exact) and `convolve` accept a map declared axial and average its angles linearly, which breaks invariant 4.

## Decision

### 1. Declared angle semantics
`Interpretation` gains two fields. Both are declared by the researcher or proposed by an adapter, never inferred from pixels:
- `frame`: `pixel`, counter-clockwise from +axis 1 towards +axis 2 as stored; or `sky`, east of north (IAU). The north direction is taken from the file's WCS at each pixel.
- `quantity`: what the angle is.
  - `b_field`
  - `gradient`
  - `dust_polarization`: the E-vector of emission, perpendicular to B.
  - `starlight_polarization`: parallel to B.
  - `unspecified`

The VGT run adapter proposes `frame=pixel, quantity=b_field`, citing the pipeline's ψ = ½·atan2(U, Q) + π/2.

A comparison or overlay across datasets converts both sides to sky-frame B-field orientation. `gradient` and `dust_polarization` are rotated by 90°. The pixel frame is converted with the local north angle that astropy computes from the WCS at each sample. If either side has `unspecified` quantity or no frame, the operation is refused, and the refusal names the missing declaration.

Single-map statistics (the existing mean orientation and resultant length) stay available without these fields, because they do not mix frames.

### 2. Axial-aware resampling everywhere
Every operation that combines several angle samples into one value works on the doubled angle: Q = w·cos 2θ and U = w·sin 2θ, with w the declared reliability, or 1 when none is declared. Q and U are resampled independently, and the result is θ = ½·atan2(U, Q). These operations are reprojection, convolution, display downsampling and block means.

The resultant length is kept as a derived reliability. Nearest-neighbour sampling is exempt, because it picks one sample and averages nothing.

`align` and `convolve` on an axial map switch to this path, and their provenance says so. Moment, slab and scalar difference on an axial map are refused, as the scalar difference already is.

### 3. A scene per pane
A pane draws a `Scene`, which has a versioned schema (`scene/1`) in `packages/contracts`:
- `base`: the dataset, the channel or spectral slab given by its world value and index, and the display settings (colour map, stretch, limits, shared-scale group).
- `overlays`: an ordered list. Each overlay has `kind`, `datasetId` and kind-specific settings.
  - `contours`: levels as an explicit list, or a generator (start, step or factor, count) in the overlay dataset's own unit; plus a channel or slab.
  - `orientation`: sampling step, length (fixed, or scaled by reliability), reliability threshold.
  - `catalog`: a catalog dataset, and the columns used for position and an optional angle and its uncertainty.
  - `regions`: saved regions.
  - `beam`: drawn only from the header's BMAJ, BMIN and BPA, never a default.
  - `grid`: a coordinate grid.

Overlays are placed by WCS geometry, not by resampling data:
- Contours are traced on the overlay's own grid, and their vertices are transformed pixel → world → base pixel.
- Orientation samples are taken on the overlay's own grid. Positions are transformed the same way, and angles are carried through the sky frame into the base pixel frame.
- Catalog positions are transformed world → base pixel after converting between the declared celestial frames with astropy.

The worker does this geometry (a new interactive-lane request that returns vertices and segments), so the browser never receives the overlay's array. If the celestial frames cannot be related, the overlay is refused with the reason. Overlay data is never interpolated onto the base grid for display, so there is nothing to mislabel as resampled.

### 4. Linked views
Panes join a user-named link group. A group can link the cursor (by sky position), the channel (by spectral world value in a common unit and frame, using ADR 0040's conversion), and the pan/zoom (by sky region). A pane can leave its group.

The same-grid check stays as a fast path. Different grids link through the WCS transformation, and the link pill shows which kind of link is active. When the spectral frames differ (for example LSRK and TOPOCENT), the channel link is refused, because frame changes are out of scope (ADR 0040).

### 5. Figures are scenes
A figure stores its `Scene` plus each dataset's identity at save time: id, size, modification time, and the fingerprint once Stage 5 adds it. The PNG becomes a cached render of that scene.

"Draw again" re-renders the scene. If a source changed, it says so before drawing and never swaps data silently. SVG export writes the vector layers (contours, segments, catalog markers, regions, axes, beam, colour bar) as SVG over the embedded raster base. Review snapshots keep freezing the rendered PNG and the scene, so a reviewer's view never changes after publishing.

## Alternatives
- **Reproject overlay data onto the base grid for display.** This is simpler, but it resamples, needs axial care for every display, and blurs contours across grids. Geometry transformation is exact and moves less data.
- **Keep linking by identical grid only.** That fails the main use, comparing GASKAP, GASS, MAGMA and Planck on their native grids.
- **Infer the angle convention from the pipeline name.** That is an adapter's proposal, not a fact. Keeping it declared, with the adapter's proposal labelled as such, matches invariant 7.
- **Put figures in a separate rendering service.** That would be a new service for one user, and the browser renderer (ADR 0034) already draws the scene.

## Consequences
- The catalog needs a migration for the two interpretation fields. Existing axial declarations get `frame` and `quantity` as unknown: they keep working for single-map statistics and are refused for cross-dataset use until declared. VGT imports are re-proposed on the next rescan.
- New worker requests: overlay geometry (contours, orientation samples, catalog positions) and local north angle.
- The viewer state moves from per-pane fields into a scene object, so this is a refactor of `useViewer`. It is done before any new overlay kind lands, and the overlay slices land one after another.
- The figure model changes, and old figures stay PNG-only: they render as before, with no "draw again".

## Validation
- Golden tests computed independently in the tests with astropy:
  - the local north angle at known WCS positions (including a rotated CD matrix and a Galactic-frame file);
  - pixel ↔ sky angle conversion;
  - the 90° rotations by quantity.
- Axial resampling: a 1°/179° pair averages to 0°, not 90°; two orthogonal angles give a degenerate resultant that is flagged; the result matches the doubled-angle reference.
- Overlays:
  - a contour of a synthetic Gaussian on grid A lands at the same sky position on grid B;
  - catalog markers land at their known pixels;
  - an incompatible frame is refused.
- Linked views: a sky cursor maps to the same world position in both panes within half a pixel; a different spectral frame refuses the channel link.
- Figures: draw-again of an unchanged scene is pixel-identical to the cached PNG; a changed source is announced; the SVG contains the vector layers.

## Rollback / Migration
- The interpretation fields are additive (nullable).
- `scene/1` figures can be drawn as PNG by older code, since the PNG is kept.
- Reverting the axial resampling would bring the invariant-4 bug back, so it is not reverted.

## Implementation notes: first slice (sections 1 and 2)
Status: implemented for the declaration, the worker conversion and axial resampling; overlays, linked views and figures as scenes are not built.
- **Declaration.** `interpretations.frame` and `.quantity` (nullable, schema 7), validated by the API, editable in the orientation panel. Existing rows are unknown. The VGT run adapter proposes `pixel` and `b_field`, and says it is from the pipeline's convention (ψ = ½ atan2(U,Q) + 90°). A map an analysis makes keeps its input's unit, frame and quantity as a proposal by `vesqira-analysis`, with the companion reliability map as its reliability.
- **"Sky" means east of north in the file's own celestial frame** (RADESYS for RA/Dec, Galactic for GLON/GLAT). Comparing files in different celestial frames rotates the position angle between the frames (astropy `directional_offset_by` and `transform_to`), so a Galactic-north direction is not mistaken for celestial north.
- **Worker.** `orientation.py` holds the conversions, all through astropy's WCS and `SkyCoord.position_angle`; the worker op `orientation_sky` converts one pixel to sky-frame B-field orientation and refuses, naming the missing declaration, when the frame or the quantity is unknown or `unspecified`. No route or screen uses it yet.
- **Resampling.** `align` and `convolve` of a declared axial map resample the doubled angle. `align` needs the frame (a pixel-frame map goes to sky position angle, is resampled, is rotated into the reference's celestial frame if it differs, and comes back to the reference grid's own pixel frame, so the physical orientation survives a rotated grid); the quantity is not needed because the same quantity goes in and out. Nearest-neighbour picks one sample, so θ itself is resampled, but the frame conversion still applies. `convolve` applies the kernel in the stored frame and does not need a declared frame. Moment and slab are refused (API and worker).
- **Companion reliability.** The result's reliability map is R = |(Q, U)| / ŵ, where Q, U and ŵ are the resampled components and weight (w is the declared reliability, or 1), so R is in [0, 1] (clipped only for round-off). Where R is below 1e-6 the orientation is undefined: θ is NaN and the pixel is counted in the summary. For nearest-neighbour, the companion is the declared reliability picked with the same sample, and there is none when none was declared. Remote analysis jobs run the same program with the same options and register `result.reliability.fits` too.
- **Display downsampling.** Disabled for axial maps, not made doubled-angle aware: the browser asks for full resolution (`useViewer`) and the API refuses `step > 1` for a declared axial map (400). A reduced preview of an angle map cannot show orientation honestly at the zoom where it is used, and the full plane is bounded by the viewer limit anyway.

## Implementation notes: second slice (section 3, the scene model; figures store their scene)
Status: implemented as a behaviour-preserving refactor with the contract. No new overlay kind is drawn, panes link only on an identical grid, and there is no "draw again" or SVG export yet.
- **Contract.** `Scene` (`scene/1`) and its parts are in `packages/contracts/bodies.json`; the web types are generated from it (`apps/web/src/scene/scene.ts`). The base is the dataset, the channel index, its spectral world value as the worker reported it (absent until read), and the display: `mapping` (scalar, or axial for a declared orientation map, drawn with twilight whatever the scalar settings), colour map, stretch, range, custom limits and unit, and the shared-scale group. The overlay union defines all six kinds, each with a required single-value `kind`. The view is zoom (1 to 16, relative to the fitted image) plus an optional centre in image pixels, so a scene shows the same image window, width/zoom by height/zoom pixels around the centre, on any pane. Shared fixtures (`packages/contracts/fixtures/scenes.json`) are accepted or refused by the Go parser and round-tripped by the web tests.
- **Viewer state.** A pane is a scene plus ephemeral state. `paneReducer` and `sceneReducer` take plain, serialisable actions: `setChannel`, `setSpectral`, `setDisplay`, `addOverlay`, `updateOverlay`, `removeOverlay`, `moveOverlay`, `setView`, plus `resetForDataset` and `syncAxial`. In a patch, null removes a field. An action that changes nothing returns the same object. `setSpectral` and `syncAxial` record facts, not commands, so a future undo stack skips them. `useViewer` keeps its setters as wrappers over dispatch and adds `scene` and `dispatch`. Opening a dataset starts a scene on channel 0, fitted, with no region; colours and the orientation-line setting carry over, as before. Saved regions are server rows, and the regions overlay copies the shapes it draws.
- **Rendering.** One registry maps an overlay kind to a pure function that returns marks (lines, rectangles, circles in picture coordinates). The viewer turns the marks into the same SVG elements as before; a figure strokes them on its canvas with `strokeMarks`. The orientation lines of the base map and the regions (saved, working, being drawn) go through it. A kind with no renderer draws nothing.
- **Figures.** A plane or orientation figure sends `figureScene(live)`, the projection of the live scene onto the picture: the drawn channel, twilight for an axial map, the line step the figure used, whether a reliability map set the line opacity and which one, only the working region, and the fitted view (a figure shows the whole plane). The figure's overlays are drawn from that projection; when it cannot state the display (a custom range without valid limits) the figure is saved without a scene but drawn the same. The server reads it strictly (`internal/scene`): unknown keys and kinds, null or non-finite numbers, out-of-range values and over-long lists (16 overlays, 256 saved regions, 64 KiB) are refused. It also refuses the four kinds not drawn yet, a scene that disagrees with the figure's dataset, channel, spectral value, display, working region or declaration, an overlay from another dataset, reliability opacity that does not name the declared reliability map, and any scene on a spectrum figure. The server stores its own re-marshalled reading in `figures.scene` (schema 9) and hashes it into the evidence revision only when present, so a figure saved without a scene gets the revision it always would have.
- **Why not inside provenance.** The provenance document is reviewer-safe and is copied as is into snapshots, published reports and the PNG download, and ADR 0011 bans dataset ids there. A scene names dataset ids, so it is owner-side only (`Figure.scene`), and the reviewer test checks that no scene reaches a reviewer.
- **Linking.** The compare panes form a link group (`scene/link.ts`): an id, its panes, a basis (only `same-grid` exists) and the linked facets. The cursor and channel facets are linked, and the view is not, as before. `follow()` returns the actions that make one pane follow another, so a WCS basis can arrive without changing the callers. While the colour scale is shared, both scenes carry `scaleGroup`, also after a pane opens another dataset.
- **Behaviour change.** Zoom now keeps the image point at the pane's centre, instead of the screen offset. A pan survives a pane resize as an image position.
- **Deferred.** Drawing the other overlay kinds, and the worker's geometry request. Linking by WCS, and user-named groups. "Draw again" and SVG export from the stored scene. The scene holds today's layers and display settings, but the base raster also depends on the theme's no-value colours and the resolution the canvas was drawn at, which are not recorded yet. A reviewer-safe frozen scene in snapshots, with dataset ids replaced by source identities, and the per-dataset identity list for multi-dataset figures (section 5). The overlay list UI. Undo.

## Implementation notes: third slice (section 3, overlays from other datasets; the overlay list)
Status: implemented for contours, orientation lines of another map, the beam and the celestial grid, on screen and in figures. Catalog markers are not drawn (a figure still refuses them). Linking by WCS, "draw again", SVG export and undo are not built.
- **Worker.** `overlay_geometry` (interactive lane, `overlay_geometry.py`) returns geometry in base pixels (0-based, centres at integers, y up) as a frame like a plane's: a JSON head, then float32 paths (group, vertex count, then x, y pairs) or orientation segments (x, y, angle, weight). Positions go overlay pixel → world → base frame → base pixel through astropy (`pixel_to_world`, `SkyCoord.transform_to`, `world_to_pixel`) on each file's celestial WCS (`orientation.celestial_wcs`).
  - **Frames.** The frame is the one astropy's `wcs_to_celestial_frame` builds, with the FITS standard default when the header is silent (ICRS with neither RADESYS nor EQUINOX; FK4 or FK5 from EQUINOX), and its status is the readout conversions' (ADR 0040: declared, inferred, assumed). Each overlay's basis text says so ("base frame ICRS (assumed: FITS default, header declares no RADESYS or EQUINOX)"). A file is refused only when no frame can be built or it is not ICRS, FK5, FK4 or Galactic. Footprints are compared both ways on a 33 × 33 sample of each image; no overlap is refused, saying so.
  - **Contours.** Traced by contourpy (matplotlib's contour engine, a new pinned dependency: `requirements.txt`, the RPM spec and its CI image; imported lazily, so a host without it refuses contours by name and serves everything else) on one channel of the overlay's own grid, NaN masked so a pixel with no value is a gap. Levels: a list, linear or geometric generators, or k × σ with σ = 1.4826 × MAD of the channel's finite pixels (`astropy.stats.mad_std`), labelled as the scatter of the whole plane, signal included. Levels are in the overlay's own unit; a scene level unit that is not the file's (or the declared one for a file without BUNIT) is refused, and a file with no unit is said to have none. A figure records the σ it drew with; a recomputed σ that differs is refused. Contours of a map declared axial are refused. Vertices outside the base (beyond 2 px) are dropped and the line split. Over 200 000 vertices, polylines are simplified (Ramer-Douglas-Peucker, written here: display only, endpoints kept, tolerance 0.1 to 4 base pixels, the smallest that fits) and the head reports the tolerance and counts; beyond that it is refused. Tracing is bounded at 2^27 pixel-levels per request, and more than 2 000 000 traced vertices are refused before any is transformed (measured on this machine: a noisy 4096² plane traces 17.5 M vertices at one level in 2.0 s; transforming 2 M vertices pixel → world → FK5 → pixel takes 0.85 s; the interactive lane times out at 30 s).
  - **Orientation.** Single pixels of the overlay map on its own grid (never block means), every `step` pixels: given, or chosen so samples are the requested spacing apart in base pixels (the pane's gapPx divided by its scale, quantised to powers of √2 so a small zoom refetches nothing). Each sample becomes sky-frame B-field orientation (`to_sky_b_field`, refused naming the missing frame or quantity), is rotated into the base's celestial frame when it differs (`rotate_pa_frame`), and into the base's pixel frame at its new position (`sky_pa_to_pixel`). With the declared reliability map (same grid, same host, unchanged), weight = reliability / its 99th percentile clipped to [0, 1], NaN where unknown; a threshold drops samples below it or unknown. Capped at 20 000 samples by raising the step (reported).
  - **Beam.** From the named dataset's (base or other) BMAJ, BMIN, BPA only: absent BMAJ/BMIN, BMIN > BMAJ, or an elliptical beam without BPA is refused; a circular beam without BPA is drawn and says so. The ellipse is built on the sky (73 points by `directional_offset_by` around a corner's sky position, BPA rotated into the base frame when the beam's file is in another) and placed by the base's WCS, so a rotated or non-square grid shows its true shape.
  - **Grid.** Lines of constant longitude and latitude in ICRS, FK5 J2000 or Galactic, spaced in whole time units (RA) or degrees, generated on the sky, converted to the base frame and placed by its WCS; a pole inside the image extends the longitudes. Labels sit where a line leaves the image, longitude at the bottom and latitude at the left by preference, never within 15 % of an edge of another label.
- **API.** `POST /api/datasets/{id}/overlay-geometry` with `{overlay, spacing?}`; the overlay is read by the scene parser (`scene.ParseOverlay`). Every file is authorized as a plane read (roots, unchanged since registered) and must be on the base's machine. The overlay's declared unit, axial declaration, angle convention and reliability map come from the catalog, never the request. The cache key holds both file identities and declared units, the reliability map's identity, the declarations, the geometry settings (not id, visibility or style) and the spacing. `overlay_geometry.py` is deployed to remote hosts with the other worker files.
- **Scene.** Contours (with the `sigma` level mode and an optional `unit`), beam (`corner`), grid (`frame`) and the orientation fields `length: reliability` and `threshold` are accepted, all with an optional style: a palette colour (`white`, `cyan`, `amber`, `magenta`, `lime`, the `--overlay-*` tokens, light inks because the image canvas is dark in both themes), a width and a dash. The server re-marshals every kind with all its fields.
- **Web.** `useOverlayGeometry` keeps one entry per overlay (computing, ready, or refused with the server's reason), replaced when what it depends on changes (a busy or unreachable worker is asked twice more; a 4xx is a refusal; automatic spacing waits for the pane's scale), so the registry's pure renderers draw only geometry that matches the scene. Contours negative levels are dashed. The **Overlays** inspector section lists the scene's overlays in drawing order: show or hide, move, edit, remove, add (kind, dataset, kind settings, style); each row states its basis or its refusal. The base map's own orientation lines and regions can be hidden and moved but not removed. This section is built from the existing controls and was not put through the design-approval gate.
- **Figures.** A figure waits for overlays still being computed, leaves hidden and refused ones out (so a hidden overlay is neither checked nor authorized), records the σ and the orientation step it drew with (the screen's geometry, so the stored step reproduces the drawn samples), strokes the same marks layer by layer in scene order, clipped to the picture, and prints each overlay's basis in the caption. The server accepts overlays from other registered datasets on the same machine (regions and the grid stay the base's), authorizes each file, and names each in the provenance by file name, size and time (never by id, ADR 0011).
- **Deferred.** Contours of a spectral slab (only one channel; a slab needs a declared aggregation and changes the unit). Catalog markers (drawn in the fourth slice). Refetching orientation geometry at the figure's own scale (a figure uses the screen's step and records it). The per-dataset identity list for multi-dataset figures and lifecycle impact for an overlay's dataset (archiving it does not list figures that drew it). A mechanical check that the list of worker files deployed to remote hosts (in `main.go`, `tools/build-rpm.sh` and four tests) matches what `plane_worker.py` imports.

## Implementation notes: fourth slice (section 3, catalog markers and vectors)
Status: implemented on screen and in figures: markers, optional orientation vectors, colour by a value, a row filter, counts of every row not drawn, the clicked row and a keyboard list. No schema change. Linking by WCS, "draw again", SVG export and undo are not built.
- **The declaration is the authority.** A catalog overlay names the dataset and only the settings below. The position columns, their format and frame, the angle column and what the angle is come from the catalog's stored declaration (ADR 0044), never from the scene or the request: a missing or stale declaration is a 409, and the declaration is part of the geometry cache key, so redeclaring a frame or a quantity is never answered from the cache. The scene's earlier `columns` object (specified in slice 2 and never drawn) is gone: it would have been a second, unchecked source of the same facts, and `scene/1` refuses it as an unknown key. Nothing stored used it, because a figure refused the kind.
- **Scene.** `catalog` overlay: `vectors` (boolean), `lengthColumn`, `lengthScale` (base pixels per unit, only with a length column), `colorColumn`, `filter {column, sigmaColumn?, min}`, and the usual style. Column names are checked against the catalogued header (they exist and hold one value per row) by the API for the overlay route and for a figure save; the worker checks again against the real table. A catalog overlay needs a point catalog and every other kind refuses one (409), checked both ways.
- **Worker.** `overlay_geometry.catalog` (called by the op `overlay_catalog` in `plane_worker.py`, which is on the heavy lane: a table is parsed there, as ADR 0044 requires; the op is not named `catalog_*` because that prefix routes to `catalog_op`). It reuses `catalog_table.convert` (positions in the declared frame, the report) and the placement of slice 3: `SkyCoord` in the declared frame, `transform_to` the base's frame (frames by `convert._frame_status` and `_sky_source`, so the FITS default rules and their status are in the basis text), `world_to_pixel`. The catalog frame is stated as "declared by you", never as read from a header. The angle path was factored out of the orientation samples into `carry_to_base` (rotate the sky position angle into the base's frame, then into the base pixel grid by its WCS) and both kinds call it.
- **Angles.** A vector is the declared angle converted to sky-frame B-field orientation by the ADR 0042 rule (`orientation.to_sky_b_field`: starlight and B-field unrotated, dust polarization and gradient +90°), carried into the base's frame and pixel grid. Vectors are refused, naming the declaration, when the catalog declares no angle column, or the quantity is not declared or `unspecified`. Markers need neither. An angle is an orientation, so the vector is a headless segment through the marker.
- **Length.** Without a length column every vector is 6% of the base's shorter side. With one, a vector is `value × scale` base pixels: the scale is given (`lengthScale`) or the one that makes the 99th percentile of the drawn positive values 6% of the shorter side, and the overlay states the number it used. A missing, unreadable, zero or negative value draws no vector (counted), never a default length. Nothing is clipped.
- **Colour.** Linear viridis between the smallest and largest drawn value, both stated (the legend in the overlay row prints them with the column and its unit). A row with no value is drawn hollow, so colour is never the only cue: the list and the popover give the numbers.
- **Filter.** `value / sigma >= min`, or `value >= min` without a sigma column. A row whose value or uncertainty is missing, unreadable or (for sigma) not positive does not pass and is counted as unknown, not as below. There was no filter on main to reuse (no `relorient.py`, no SNR rule in the repository), so this is the first and defines the semantics; a later relative-orientation filter should call the same rule.
- **Every row is counted once.** `no position` (empty or unreadable cell; the basis says "N rows not drawn: see the catalog's parse report" and counts non-row lines of the file), `outside` the base's footprint (a position that lands off the image, including one the projection cannot place, such as the antipode of a TAN reference point), `filtered`, `drawn`; the worker asserts the four sum to the table's rows. Footprints are not an error: a catalog that misses the map is drawn as zero rows with the counts saying why.
- **Bounds.** At most 200 000 table rows per overlay (astropy's transform of that many takes about a second) and 20 000 drawn markers (480 KB of float32, and the same number of SVG circles); over the second the overlay is refused with "add a row filter", never truncated. The frame is six float32 per drawn row (x, y, vector angle, vector length, colour value, row), the head only counts and sentences.
- **Web.** The registry's `catalog` renderer returns `marker` marks (a ring of 4 output pixels in the overlay colour, filled by the value) and the vectors as line marks; `Marks` skips markers and the viewer draws them in the screen-pixel layer beside the labels, `strokeMarks` draws them on a figure with a dark halo. A click on the canvas hit-tests the nearest marker within 9 screen pixels (`nearestMarker`) and opens a small popover with the row as the file gave it (`catalog/rows`, a missing value said as missing, the line in the file); Escape or the close button closes it. The overlay's row in the inspector has the legend and a list of the drawn sources: a button per source (paged by 50) that picks the same row and shows its values, which is the keyboard route. The overlay form offers only catalogs with a declaration in force and only numeric one-value columns, and disables vectors, saying what to declare, when the angle or its quantity is missing.
- **Figures.** A catalog overlay is kept in the figure's scene when its geometry was drawn (hidden or refused ones are left out, as for the other kinds), the caption prints its basis (frames and their status, the vector conversion and scale, the colour range, the filter and every count), and the server checks the same declaration, columns and quantity (it does not run the worker when saving). The provenance says the catalog's columns, frame and angle meaning were declared by the author of the board, not by the file, and names the file by name, size and time, never by id.
- **Validation.** Worker golden tests compare placed rows with astropy on a rotated base (within 0.5 pixel) and a Galactic catalog on an ICRS base; a starlight angle of 0 points to base north on a rotated base, dust polarization to base east, 180 equals 0, and a Galactic north angle follows Galactic north; an undeclared or `unspecified` quantity is refused by name; the counts partition the rows with a filter that has kept, below and unknown rows; an antipodal row is outside; length scales, colour range and the marker budget are checked. Go tests run the real worker through the route (spec conformance, declaration changes through the cache, both-way kind refusals, a changed file) and the figure checks; web tests cover the frame, the renderer, hit-testing, the basis text, the form and the list, and an e2e spec drives a catalog over the H I cube.
- **Not done.** The design gate (these controls reuse the existing inspector components and were not put through three directions), a unit-aware length scale (the file's column unit is shown, not converted), proper motion and epoch propagation (the frame's equinox is not an observation epoch), per-row frames, and thinning instead of refusing very large catalogs.

## Implementation notes: fifth slice (section 4, linked views)
Status: implemented for the compare view's two panes: user-named groups, the cursor, channel and view facets, leaving and rejoining, same-grid fast path unchanged, and linking different grids through the worker's WCS transformation. More than two panes are not built (the layout has two). The design gate was not run: the controls reuse the existing Select, Checkbox, Input, Button and Pill and sit in the compare bar.
- **Groups (`scene/link.ts`).** `LinkPrefs` holds what the person chose for the pair: the group's name (1 to 60 characters, "Compare" when blank), the three facets (cursor and channel on, view off, as before), who has left, and whether different grids are linked by WCS. `linkGroup(prefs, sameGrid)` is the group, or null when fewer than two panes are in it or the grids differ and WCS linking was not chosen. Same grid still links on its own. Different grids are not linked until the person presses **Link by WCS**, so the existing "not linked, nothing is resampled" statement and its reasons stay what the person sees first. **Unlink map A / B** dissolves a pair (a group needs two panes) and **Link again** rejoins. Prefs belong to the pair of datasets and start over for another pair.
- **The pill states its basis.** `linkPills` builds the text: "Same grid: cursor and channel are linked" (the fast path, no worker call); "Linked by WCS: frames ICRS↔Galactic (astropy), cursor within 0.03 px in this view" (or "frame ICRS" when both are in one frame), called approximate and warn-toned from 0.5 px; "Cursor link refused: <reason>"; and, separately, "Channel linked by spectral value" or "Channel link refused: spectral frames differ (LSRK vs TOPOCENT); changing frame is not offered". A refused channel never blocks the cursor. For the active pane's channel the bar also says, for example, "B channel 41 is 0.12 km/s from A's 8 km/s", or that A's value is outside B's spectral range and B does not follow.
- **Worker (`link` op, no new file).** `overlay_geometry.link_sky` and `convert.link_channels`, reached by one op in `plane_worker.py` that authorizes `other_path` like `overlay_path`, so both are deployed already. Sky: A pixel → world (A's frame) → B's frame → B pixel through `overlay_geometry.Sky` and `to_base` (the frame rules and statuses of the overlays, ADR 0040's FITS defaults), returned as an affine approximation fitted on a 7 × 7 grid over the region of A in view, its worst and rms error measured on a different 21 × 21 grid (corners included) in B pixels, the pixel-size ratio, B's shape, and the exact positions of up to 64 requested points. A region where the transform is undefined is refused, not approximated. The browser applies the affine, so hover is local; it asks again when the view leaves the region it asked (asked with a 25 % margin and widened to a half-pixel grid by the server, so a small pan hits the cache) or becomes much smaller (a tighter bound), keeps the last answer meanwhile, and never extrapolates outside its region ("computing the link…"). The pill states the bound of the view on screen. The region is the pane's real window (`visibleWindow`, from the pane's measured size: a pane wider than the image shows more than image / zoom across), with the margin.
- **Channel.** One reply holds A's every channel → B's nearest channel, the residual in A's axis unit, and "outside" (beyond B's range by more than half a channel: B does not follow and says so), computed once per pair and direction. The nearest channel is found by value over all of B's channels (axes may run backwards). Rules: SPECSYS must be stated by both and equal (a missing one is "not stated", never "same"), so the frame of a legacy `VELO-LSR` axis is its CTYPE suffix; two velocity axes of the same convention compare as velocities, a unit change only, each file's own line, so H I links to CO by velocity; a velocity against a frequency or wavelength goes through the velocity file's rest frequency and convention (ADR 0040's doppler equivalencies), refused when the other file states a different rest frequency, and the rest used is named in the basis; a legacy velocity axis links only to another one; different conventions are refused. No convention is chosen by the person here because none is needed: the residual is in A's own unit, and the file declares what the conversion needs.
- **Following.** `useLinkFollow` serves both bases (same grid through `follow()`, WCS through the worker's tables). It reacts to a pane's own change of channel or view, never to which pane is active (nearest channel and clamped zoom are not invertible, so following the active pane would make the other jump when the inspector switches), ignores the change it made itself, lets the active pane lead once when a facet is switched on or its transform arrives, and follows the pane that last led again when a view transform is replaced. The view is carried by centre and zoom: the centre through the affine, the zoom by the pixel-size ratio. This is approximate and stated so: a rotated grid shows a similar, not the same, region, and zoom stays within 1 to 16. The cursor marker is drawn on the nearest pixel (never outside B: "Cursor is outside this map's footprint" appears in that pane's header instead), and the readout's "Other map" row reads B at that pixel, or says it is outside or still computing. The exact `points` of the route are not used by the UI yet (the marker is on a pixel, and the affine error is stated).
- **Scene.** `scene/1` gains an optional `link` (`SceneLink`: id, name, basis `same-grid` or `wcs`, the three facets, and 2 to 8 distinct dataset ids that include the scene's own), added strictly (additive, no version change): the Go parser refuses unknown keys, a null, a missing facet, a bad name (control characters, over 60 characters) and a group that leaves out the scene's own dataset. The shell records each pane's group with `setLink` and a figure's scene carries it, so a figure says how its panes followed each other. It is owner-side like the rest of the scene (dataset ids never reach the provenance a reviewer sees; a test checks the name and `datasets` stay out of it). Opening another dataset in a pane starts without a link.
- **API.** `POST /api/datasets/{id}/link` with `{otherId, region?, points?, channels?}` returns the worker's reply (`LinkReply`, described in `bodies.json`, so `undescribed.txt` did not grow; no schema change). Both files are authorized as a plane read, must be on one machine, and a point catalog is refused (409); a pair that cannot be related is a 200 with the reason in `refused`.
- **Validation.** `test_link.py` compares the worker with astropy used directly: ICRS to Galactic cursor positions (within 0.5 px, in fact 1e-3), a grid rotated 30 degrees, a point outside B's footprint (still reported, `inside` false), the affine's stated error against a dense independent grid over a 100-degree field and over smaller regions (the bound holds, is not flattering at 100 degrees, and shrinks with the region), channels for a radio velocity axis against a frequency axis with residuals and "outside", a reversed axis, H I against CO velocities, SPECSYS differing (the text above) or missing, conventions, rest frequencies, legacy axes and a file with no spectral axis. `link_test.go` runs the real worker through the route (spec conformance of request and reply, the cache answering a repeat and a small pan, the topocentric refusal, the request's own refusals) and the figure test stores and refuses links. Web tests cover the group rules, the scene action and fixtures (accepted and refused by both sides), mapping, view and channel following, the pill's words and the controls; `yy-linkedviews.spec.ts` links an ICRS cube to a Galactic one in a real browser, checks the marker, the footprint note, the channel sentence, a refused frame, unlinking and an axe scan of the controls.
- **Fixed: spectral frames on the same-grid path.** The grid check (`internal/compat`) compares axes, not SPECSYS, so two cubes on one grid whose spectral frames differ (LSRK and TOPOCENT) were once linked channel by index with no frame check. `compat.SpectralFrames` now answers that separately and `GET /api/compat` returns it as `channelLink: {ok, reason}`; it is deliberately not a grid reason, because many images carry no SPECSYS and the cursor and view links concern sky position, which RADESYS already guards. Both cubes with a spectral axis must declare SPECSYS and agree (case and spaces ignored); a missing one on either side is a refusal, never "same"; a file with no spectral axis has no channel to link. A legacy CTYPE suffix (`VELO-LSR`) states its frame only when SPECSYS is absent, as the label "legacy CTYPE suffix LSR", which equals only the same suffix on the other file (it is not equal to `LSRK`), and a SPECSYS beats the suffix; this is the reading the worker's channel link uses. When refused, the same-grid group keeps its cursor and view facets, turns the channel facet off (the box is disabled) and the pill says "Same grid: cursor linked; channel link refused: <reason>"; the WCS path words its own refusal the same way. Tests: `compat_test.go` (every case), the compat route's reply against the spec, `linkGroup`/`linkPills`/`follow` and the controls in the web tests, and `yy-linkedviews.spec.ts` with `hi_cube_topocentric_same_grid.fits` (the base cube with SPECSYS changed).
- **Viewports.** Looked at only at 1440 × 900 in the dark theme (screenshot of the compare bar and panes); 1280 × 800, 390 × 844, the light theme and a keyboard pass were not done for these controls.
- **Not done.** More than two panes and a group menu (the compare layout has two); the exact `points` for a pinned pixel; a spectral convention chosen by the person for the residual (not needed today); linking a view for a rotated grid exactly (the view is a centre and a zoom); the design gate.

## Implementation notes: sixth slice (section 5, draw again, the change announcement and SVG export)
Status: implemented for figures saved from now on: "draw again" for plane, orientation and channel-grid figures, the announcement of what changed in each file, linked new revisions, and SVG export of plane and orientation figures from the figure panel and from a board item. A figure saved before this slice, or a spectrum figure, is shown as its PNG, says so, and has no such buttons. Linking by WCS and user-named groups are another slice and are not touched. The design gate was not run: the two panels reuse existing controls (`Button`, the board card), with no new screen.
- **What a figure now records.** `scene.render` (scene/1, additive and optional, parsed strictly): the canvas size the plane was drawn on, the two no-value colours the theme gave (the hatching), and the width the figure was composed at. These are the facts the second slice named as missing from the base raster. A canvas larger than 2^26 pixels (256 MiB of RGBA, the most a redrawing allocates; the server holds the same bound) is not recorded: the figure keeps its scene and is drawn from its PNG only, instead of the save being refused. A channel-grid figure records `render.figureWidth`, `render.overlaysNotDrawn` (the caption states the count) and `render.scaleSource`, the whole sentence on where the shared scale came from (`display.source` keeps only its first 190 characters, so the caption could not be reproduced from it). A figure without them is "PNG only": the check route says so (`state: none`) rather than drawing at another resolution, which would not be the same picture. The title is baked into the PNG but stays editable text; a redrawing uses the figure's current title, so editing it is one way an unchanged scene differs from its PNG. The no-value colours are read by `viewer/nodata.ts`, for the viewer and for the save.
- **The comparison is on the server.** `GET /api/figures/{id}/redraw-check` lists the base and each overlay's dataset once and compares what `figures.identity` recorded (ADR 0053) with the registered record and with the file as it is, using `identity.Relate` and the same `differs` words as the newer-result notices. Per file:
  - `unchanged`: equal full SHA-256. Time alone may differ ("only its modification time differs").
  - `probable`: size and time match and nothing computed differs, but the evidence cannot prove the bytes equal: only a sampled fingerprint (it has a blind spot), none recorded, no identity recorded (a figure saved before ADR 0053), or a file on a host (not looked at here). Requiring a full hash would make every large cube "probable" for good, so the rule is the evidence the figure holds, said as it is.
  - `changed`: size, time or a fingerprint differs from what the figure recorded, and the file is registered so it can be read. It names what differs.
  - `changed_on_disk`: the file is not what is registered (a read is refused with 409). It is not registered again behind the owner's back: "register it again, then draw again".
  - Files listed: the base (`source`), each overlay's dataset (`overlay`) and each reliability map a visible orientation overlay reads (`reliability`: the one the overlay names, or the dataset's declared one when only the length or a threshold uses it). A map that sets the opacity, length or threshold of lines decides how the picture looks, so a figure saved from now on records its identity as a third role and a change in it is announced like a change in the source. A figure saved with no record of one lists it as `probable`.
  - `missing`: no longer registered, not found, or not allowed. A verified copy on this computer counts as readable (the read order of ADR 0053) and the sentence says it was read from one.
  - The state is `ready` (every file unchanged: draw), `ask` (some changed or probable, all readable), `blocked` (one cannot be read) or `none`. The sentences are built in `internal/server/redraw.go` and tests pin them, among them "Drawing from changed data makes a different figure; the original PNG is kept. Draw it again anyway?" and, when only `probable` files are involved, "Some data cannot be proven unchanged. Drawing from different bytes makes a different figure; the original PNG is kept. Draw it again anyway?". The route is owner-side (it returns dataset ids, which the scene it describes holds too) and changes nothing.
- **Drawing again** (`viewer/redraw.ts`) reads the dataset list, the view and the plane at the recorded channel (full resolution), the declared reliability map for the base's own orientation lines, and each visible overlay's geometry from the worker (no spacing is asked: a figure recorded its step). It projects the stored scene again through `figureScene` (the projection is idempotent: a test shows projecting a stored scene returns it), draws the base raster with the CPU `renderPlane` at the recorded canvas size and colours, and composes the picture through `composePlaneFigure`, which a save now uses too (`saveViewFigure` was refactored onto it, so caption, legend, layers and view description cannot drift between a save and a redrawing). The GPU renderer agrees with the CPU one to one colour step (ADR 0034), so a figure saved from the GPU path may differ from its redrawing in a tiny share of pixels; the panel says whether the pixels are the same (decoded RGBA, not bytes) and does not call a difference an error. When the owner agreed to data not proven unchanged and the pixels are the same, it says that too, without calling the data unchanged.
- **Reliability maps and declarations.** If the map an orientation overlay recorded is not the one its dataset declares now, or the map cannot be read, or the declaration was removed, the redrawing stops and names the dataset: lines drawn from other opacities would be a different figure, not a quietly uniform one. The unit, angle frame and quantity declarations in force now are used and are **not compared** with those at save time (the figure records neither); a declared quantity that changed turns the sample angles, so a follow-up should record the declarations a figure was drawn under. A scene that differs from the stored one once the data are drawn (apart from a σ measured again, which has its own note) is said so.
- **Sigma.** A contour level recorded as k × σ is tied to the bytes it was measured on, and the worker refuses a recomputed σ that differs. For a `ready` figure the recorded σ is sent, so a file that changed in a way the identity did not show is refused instead of being drawn as the original. After the owner agreed to draw from changed or probable data, σ is measured again, the new figure records and states the new value, and the panel names the layer and both values. A layer the worker refuses now (a frame that cannot be related, no overlap) stops the redrawing with the layer named; none is left out silently.
- **A redrawing is a new figure.** `POST /api/figures` takes `redrawnFrom` (the original's id, of the same dataset and the same kind of description, else 400). The link is stored owner-side in the new figure's `figures.identity` (`redrawnFrom {figureId, revision}`, additive and optional) and is hashed into the new revision, so a redrawing with the same pixels is still a figure of its own and never finds or replaces the original; saving the same redrawing twice finds itself. There is no schema bump: identity is already the owner-side record of what a figure was drawn from, and nothing queries by the link yet (finding the redrawings of a figure is a scan of a handful of rows). If something needs to, it becomes a column in a later migration. The original figure, its revision, its pinned PNG, the boards that hold it and every snapshot are not touched (a test compares the original before and after, and the board's item). The link never reaches provenance, snapshots, reports or a reviewer.
- **SVG** (`viewer/figureSvg.ts`) is a second backend of the picture the PNG paints: the same `layoutImageFigure` (title, picture box, colour bar, wrapped caption), the same marks from the overlay registry (what `strokeMarks` strokes), and the base raster as the plane drawn at the recorded canvas size, embedded as a PNG data URL (`xlink:href`, nearest-neighbour). Contours, orientation segments, catalog markers and vectors, regions, the beam and its size, the coordinate grid with its labels, the colour bar (a gradient from the colour table with its limits and unit), the caption lines and the title are SVG elements and text. An ink element carries `data-role`, its dark halo only `data-halo`, a filled polygon's fill only `data-fill`, so counts mean something (the e2e checks that the contour paths in the file equal the contour paths on screen). No overlay id, catalog row number or dataset id is written, and a dataset the caption names is named by file name (`another dataset` when unknown), never by id. `<metadata>` holds JSON with the title, the author's caption, the reviewer-safe provenance document the PNG download carries and a software line, with any `datasetId` or `path` key removed defensively; `<title>` and `<desc>` carry the title and the caption. Everything is XML-escaped (names come from files), invalid XML characters are dropped, and the raster must be a `data:image/png;base64` URL, so no script, handler, `foreignObject` or external reference can be written (tests). A channel-map grid is panels of raster only and has no SVG.
- **Reviewers.** SVG export is the owner's: it is made in the owner's browser from the stored scene, which names dataset ids and is owner-side (ADR 0011), and the reviewer listener has the store only. Reviewers cannot download the PNG of a published figure today (they see it inline; the listener has no download route), so by "only if they can already download the PNG" they cannot download an SVG either: the listener has no route for one, and a test publishes a redrawing and checks that no scene, render record, link, `svg` or `<metadata` reaches the reviewer API and that SVG paths are 404. If a reviewer PNG download is ever added, an SVG for reviewers needs the frozen reviewer-safe scene (source identities in place of dataset ids) that section 5 still lists as deferred; it must not be served from the owner's scene.
- **Contracts.** `Scene.render`, `ChannelGrid.render`, `FigureIdentity.redrawnFrom`, `CreateFigureRequest.redrawnFrom` and the described `GET /api/figures/{id}/redraw-check` (`RedrawCheck`, `RedrawSource`); `undescribed.txt` did not grow. `fixtures/scenes.json` has one valid and seven invalid render records, read by the Go parser and the web tests.
- **Validation.**
  - Go: the comparison table (unchanged, touched with equal SHA-256, another size, another fingerprint, sampled values differing, time only, probable with equal sampled values, probable with nothing recorded, no identity) with the exact sentences; the route through real registration (ready, changed on disk, changed after reading again, missing, probable for a 20 MiB file, none for a scene without render and for a figure without a scene, 404); a redrawing is a new revision with the link while the original and the board's item are unchanged, the same redrawing finds itself, a link to another dataset, an unknown figure or figure 0 is 400; the reliability map recorded as a third role and announced when it changes; the reviewer test above; the described route and a linked redrawing in the kin-openapi conformance test; the scene and grid parsers (render accepted and stored as read, older figures marshal as before, bad records refused).
  - Web: the SVG test parses the document and counts every element by role, checks the embedded raster, caption, colour bar, metadata, escaping and the absence of ids, paths, script and external references; `redraw.test.ts` draws a stored scene with mocked services (recorded canvas size and width, the recorded σ sent, the same scene saved with `redrawnFrom`, σ measured again and stated after consent, a refused layer stops the redrawing, a changed, removed or unreadable reliability map stops it, the raster's hatching colours) and a channel-grid figure (the recorded scale and its whole sentence, columns and width, the linked save); `saveFigure.test.ts` keeps the scene but not the render record for a canvas over the bound; the component test covers ready, ask (nothing drawn before consent, nothing on Cancel), blocked, none and both SVG paths.
  - e2e (`zzzz-figure-redraw.spec.ts`, CPU renderer forced): a figure with contours and a beam is saved and put on a board, drawn again with no question, and has the same pixels as its PNG; the SVG downloads, parses, has as many contour paths as the screen, an embedded PNG and no id or path; the redrawing saves as a linked revision with the same scene and the original is unchanged; then a changed file is announced as unreadable until it is read again, then as changed, and nothing is drawn until the owner agrees; the saved redrawing has the same PNG bytes as the original when nothing changed (checked by hash, not by the app's own sentence), can be put on the board after the original, and its card says what it is a redrawing of; axe scans of the ask, blocked and drawn panels pass. The draw-again and save buttons are on the board card; the figure panel right after a save offers only the SVG export.
- **Declarations are compared too.** A declared unit, an orientation's interpretation (kind, unit, frame, quantity, reliability map) and a catalog's declaration are the owner's statements about a file, and a redraw reads the ones in force now. `figures.identity` therefore records, per source, overlay and reliability dataset, `declarations` (declared unit with who declared it, the orientation interpretation with who declared it, a hash of the catalog declaration's content with who declared it; additive, owner-side; an empty object records "none declared"). `redraw-check` adds `declaration` and `declarationText` to each source: "declaration unchanged"; "declaration changed: unit was K (declared by you), now Jy/beam (declared by you)" (orientation and catalog parts are worded the same way, with "not declared" for an absent side); "declaration removed" (nothing declared now); and, for a figure saved before this was recorded, "declarations at save time were not recorded" (not an error, not a reason to ask). A changed or removed declaration is treated like changed data: the state is `ask` with its own prompt (or a "both" prompt when the data changed as well), the owner must agree, and the new figure revision records the declarations in force when it is saved. Every declaration of a dataset the figure used is compared, also one the picture does not read (a unit declared on a map used only for lines); that is conservative on purpose. Tests pin the sentences and the route (`TestDeclarationComparisonSentences`, `TestRedrawCheckAnnouncesAChangedDeclaration...`, `figureRedraw.test.tsx`).
- **Not done, and gaps worth knowing.**
  - The unit, angle frame and quantity declarations are not part of a figure's recorded identity (see above).
  - The channel-grid redraw has a mocked unit test (recorded scale and its whole sentence, columns, width, linked save, preview step) but no pixel-identity e2e.
  - An SVG export needs the worker (it draws again): an unreachable host or a refused layer is a stated failure, not a partial file.
  - Files on a host are never better than `probable` here, because looking at them waits on the network.
