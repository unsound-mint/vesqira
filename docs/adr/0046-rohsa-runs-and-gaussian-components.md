# ADR 0046: ROHSA decomposition runs and the Gaussian components in the spectrum view

Status: **proposed; implemented, awaiting owner review.** Decided by the implementing agent under the owner's delegation of ADR decisions (roadmap Stage S). The new panel has had no design review and no owner approval.

## Context
The owner's supervisor wants to see a decomposition as curves ("if it's a decomposition, she may want to see the resulting bell curves"), the raw outputs (data, model, residual and component maps) before derived numbers, and CNM against the rest: the ROHSA side trusts only a two-phase "CNM and others" split. Vesqira's run model (ADR 0014) knew one kind, `vgt`.

A ROHSA result is, on the owner's machine: `<region>/rohsa_n<N>.dat` (or `rohsa_<candidate>.dat`), plain text with a comment header and rows `i j amp mean sigma`, one row per (pixel, Gaussian), up to tens of GB; the Fortran namelist `parameters_n<N>.txt`; `rohsa_n<N>_run_trace.toml` and `_products_trace.toml`; the crop `<region>.fits` the fit used; and a product tree `<region>/rohsa/<label>/{maps,cubes}`.

The row conventions were read from the pipeline's reader (`read_rohsa_parameters`, `reconstruct_rohsa_components`) and **checked against its own product maps on a real 128 x 128 x 4 result** (not committed): column 1 is the zero-based row of the crop (FITS axis 2, "y"), column 2 the zero-based column (axis 1, "x"), the Gaussian index runs fastest; `mean` is 1-based in channels; `sigma` is in channels; the pipeline's `mu_kms` map equals the crop's spectral axis evaluated at `mean - 1` (to the map's float32 precision), and `sigma_kms = |dv| * sigma`.

## Decision
- **Run kind `rohsa`, same model.** `POST /api/runs/import` takes a `rohsa_*.dat`, or a folder holding exactly one (and no `run_metadata.toml`). The run's key is the `.dat`'s real path (several fits share a folder). Settings come from the namelist (source `parameters`; the machine's file names dropped), the trace's `[config]` (`config`) and its top-level scalars (`run_trace`), all declared by those files; the products trace's `[fit_metrics]` become declared metrics. No commit, time or environment is recorded because the records carry none: the reproducibility facts say unresolved. A path or user name never enters the run (the rule of ADR 0014). Files outside the source roots are never read.
- **The crop is an input, found by name, never guessed.** `<region>.fits` beside the `.dat`, where region is what the trace declares, else the folder's name (labelled "inferred from the folder's name"). If it is not there, the run imports with a note and no spectral calibration; no other FITS in the folder is tried. The crop is registered as a dataset and linked in the run's record (`rohsa_runs.info`), **not** in `run_outputs`, so the dataset is never reported as produced by the run. Whether the crop is the grid the `.dat` was fitted on is checked when the file is indexed: its row count must equal pixels x Gaussians.
- **Products are outputs.** Each `*.fits` under `rohsa/<label>/maps` is registered and linked with the product's name (the file name without `<label>_`) as its role; `cubes/` files get a `cube_` prefix. Units: the file's BUNIT always wins. A map without BUNIT gets a unit proposed from its name (`_kms` km/s, `_kkms` K km/s, `_cm2` cm^-2, `_k` K) as an ordinary declared unit whose author is `rohsa-run-adapter` (labelled, replaceable, never over a person's own). A map whose BUNIT contradicts its name keeps the file's value and gets a note ("The file says K; its name suggests km/s"). The real pipeline copies the crop's BUNIT onto every map (all 36 maps of the sample say `K`, including `*_kms` and `*_nhi_cm2`), so these notes are expected; that is an upstream pipeline defect, reported to the owner, not corrected here.
- **Worker: one streaming pass, then random reads.** The `.dat` is never loaded. `rohsa_index` verifies, in 32 MiB chunks, that the file is exactly the regular layout (every row is the (i, j, Gaussian) its position says, five finite columns, lines under 512 bytes, rows = nx x ny x N) and records the byte offset of the first row of every pixel: 8 bytes per pixel in a sidecar under the cache folder (`<data-dir>/cache/rohsa`), keyed by a hash of the real path, size and mtime, so a changed file is indexed again and nothing is written next to the data. The pass is **resumable**: each call works about 15 s, saves how far it got and reports `building` with the byte progress; the page calls again. This keeps every worker request inside its 30 s limit for any file size. At the 6.7 MB sample it takes 0.16 s (about 40 MB/s per core, so roughly 8 minutes for 20 GB, once). Any irregularity refuses the file with the count and the first lines (`refused`); nothing partial is served. `rohsa_pixel` reads one pixel with one seek and N short lines and re-checks every row's (i, j) against the pixel asked for.
- **Why not the FITS component maps?** They would be O(1) and need no index, but they are optional outputs, derived by the pipeline (the owner asked for raw outputs before derived numbers), carry the unit defect above, and depend on the pipeline's own channel conversion, which would then be trusted instead of checked. The `.dat` is the one file every fit has. The maps are still imported and browsable.
- **Conventions, applied in one tested place (`rohsa.py`).** `mean_channel = file mean - 1` (0-based index; a Gaussian at raw mean 11 sits at channel index 10). Centre and sigma in km/s come from the crop's spectral axis through astropy WCS (`all_pix2world`, fractional channels allowed), sigma through the uniform channel step; the axis must be a declared velocity axis with a resolved, uniform grid, else centres and widths stay in channels with the reason. The crop has no `CUNIT3` in the real data: the FITS default m/s is used and the unit status `inferred` is carried to the reply and shown. Model = sum of components `amp * exp(-(c - mean)^2 / (2 sigma^2))` evaluated on every channel; a component with `sigma` not positive and finite is listed as invalid and not drawn (no floor is invented; the pipeline's 1e-6 floor is not copied); an amplitude of 0 is a fitted value and is kept. FWHM = 2 sqrt(2 ln 2) sigma. T_D = 121.1 K (km/s)^-2 x sigma^2, the pipeline's constant (m_H sigma^2 / k_B for atomic hydrogen, thermal broadening only: an upper limit on the kinetic temperature); the reply states it.
- **Routes** (owner listener, local files only; a ROHSA file on a remote host is refused by the worker): `GET /api/datasets/{id}/rohsa` lists the runs whose components can be drawn over the dataset: the dataset is the run's crop, or exactly on its grid (`compat.Grids`: shape, axis types, units, reference values and pixels, steps, frame, all required and confirmed). A cube with the crop's axis lengths but another or unconfirmed grid is listed with the reason (409 on use); unrelated files list nothing. `POST .../rohsa/index` advances the index. `GET .../rohsa/components?run=&x=&y=` answers 409 until the index is ready, then a frame: JSON head (components, axis, conventions in words) and float64 axis, model and per-component curves.
- **Spectrum view.** When a run applies, the Spectrum section offers a "Gaussian components" switch (off by default; nothing is read before it is on). The data drawn with the curves is the pixel's own spectrum (a one-pixel region through the existing spectrum route), not the region mean above; the pixel is the pinned one, else the one under the pointer, else the last one. Plot: data, model (sum), each component, and a residual strip drawn as **data - model** with the sign stated in the panel (the pipeline's maps use model - data); a channel with no data has no residual. Data and residual are drawn only when the dataset's brightness unit and the crop's are both known and equal. A table lists amplitude (in the crop's unit), centre, sigma, FWHM and T_D. A **CNM width cut** input defaults to 2.03 km/s, said to be the pipeline's scan-script default and the person's to change; a component is CNM when sigma is strictly below the cut (the pipeline's `s < cut`), otherwise "others". Two groups only: no LNM/WNM label anywhere. Lines differ by dash and weight as well as colour (CNM dashed, others dotted, model heavy).
- **Schema 12**: table `rohsa_runs(run_id, dat_path, info)` (the run's decomposition record; the `.dat` path stays server-side).
- **Discovery**: a folder with a `rohsa_*_run_trace.toml` is shown as a run of kind `rohsa` with the trace's settings, declared.

## Alternatives
Load or memory-map the `.dat` (20 GB of text; not mappable into numbers). A dense per-row index (8 bytes per row instead of per pixel; no gain once the layout is verified). A sparse checkpoint index (needs the same verification pass and a scan per lookup). Building the index in a goroutine (state to track across restarts; the resumable call is stateless). Treating the folder's other FITS as a crop candidate (a guess). Computing T_D from astropy constants (121.2 vs the pipeline's 121.1: the owner's CNM scan uses 121.1).

## Consequences
The first open of a very large fit costs one indexing pass (shown as progress). Only the layout ROHSA writes today is accepted; anything else is refused with a reason. Only local files. A de-rotated run's crop carries its own (shifted) spectral axis; the note in the scan script about moving centres back to the original grid is not applied, and the curves are on the crop's axis.

## Validation
Worker tests on a generated, non-square crop (6 x 4 x 40, three Gaussians, reference pixel not 1, no CUNIT3): every pixel reads back its own row (x and y not swapped); a Gaussian at raw mean 11 peaks at channel index 10; centres, sigmas and the model equal an independent NumPy evaluation and the closed form of the FITS axis; a zero amplitude is kept; invalid sigma is flagged and not drawn; the index is chunked, resumable, reused and written only in the cache folder; a changed file is indexed again; malformed, out-of-order, short and wrong-N files are refused with line numbers. Go: import declares the settings and drops locations, links the products, never gives a declaration to a file that states a unit, notes a BUNIT that contradicts the name, keeps a person's declaration, imports without a crop with a note, refuses `rms_map.dat`; components routes require the grid and an index. Web: classification at the cut boundary, the cut input, the toggle, curves, table, residual sign, unit refusal, progress and refusal. Checked by hand on a real 128 x 128 fit (indexed in 0.16 s, pixel values equal the pipeline's component maps).

## Rollback / Migration
Drop `rohsa_runs` and the three routes; ROHSA runs then show as ordinary runs of kind `rohsa` without a decomposition record. Datasets are unaffected. The cache folder can be deleted at any time.
