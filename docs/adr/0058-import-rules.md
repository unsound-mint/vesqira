# ADR 0058: Import rules: scan preview, researcher rules, explicit apply

- Status: proposed; implemented, awaiting owner review. No design review and no owner approval of the new screen (same position as ADR 0046).
- Date: 2026-11-12
- Builds the Stage 5 item "Generic import: scan a folder, review the proposed mapping, save the rules" (Q17, Q82) on ADR 0030 (projects and discovery), 0039 (writing on a host), 0044 (point catalogs), 0046 (ROHSA runs), 0053 (dataset identity).

## Context

Discovery applies built-in rules: run records, FITS, catalogs in declared data folders. Researchers' folders vary (`validation_output/rohsa/<label>/{maps,cubes}`, `data/{exp_raw,interim,sims}`, `vda/*/vgt psi maps`, text star tables). The built-in rules cannot know that `vda/*/vgt/psi_*.fits` are B-field orientations in the pixel frame, that `*_kms.fits` have unit km/s, or that `stars/*.dat` is a catalog with declared columns; the researcher does, and Vesqira must not guess it (AGENTS.md invariants 1, 7, 8).

## Decision

**Scan preview (read-only).** `POST /api/projects/{id}/import/preview` walks a chosen folder inside the project (this computer, or a host through the worker's `walk`; the project folder is already a source root, so no new authorisation) with the scanner's own rules, a depth cap of 24 on top of the entry and time budgets, and an inventory of every file nothing recognises (at most 50 000, `othersTruncated` says when there were more). Every file gets a built-in role and the rule behind it (`discover.Items`): dataset, catalog, run record, VGT output with the role the run record gives it (`psi`, `reliability`, `support`, `fit_rbar2`), file inside a run, ROHSA fit and ROHSA product, config, job template, archive, other format without viewer, file in a declared data folder, not recognised. The reply groups files by role, extension and author with counts, sizes and a bounded sample (a group opens to 500). Truncation (entries, time, depth, inventory) is reported, never silent. The preview registers nothing, writes nothing and changes no row; the walk is cached ten minutes per project (one walk per project at a time: a preview asked for meanwhile waits and uses its answer), so editing a rule is answered without walking again. The project summary's rule count is taken from whole-project walks only.

**Researcher rules.** A rule has a unique name, a kind (`glob` or `regex`), a pattern on the path relative to the project folder, a role and flat declaration fields (`discover.Rule`).
- Glob: no `/` means the file name at any depth; with `/` it is anchored at the project folder; `*` stays in one segment, `**` stands for any number of folders; case-sensitive. Regex: Go RE2 (no backtracking), searched in the whole path. Pattern length 300, 100 rules per project.
- Roles: `dataset` (optional `unit`), `orientation` (`angleUnit` deg|rad **required**, optional `angleFrame` pixel|sky and `quantity`), `catalog` (longitude and latitude columns, coordinate format, coordinate frame **required**, equinox for fk4/fk5, optional angle column with unit, quantity and uncertainty column, up to eight value columns) `mask` (the file is a typed mask of another dataset: `maskType` low_snr|saturated|invalid|user_excluded|other **required**, `maskNonzero` flagged|valid **required**, `maskMeaning` required for `other`, `maskTarget` **required**, optional `maskStrip`; see **Mask role**) and `ignore` (the file stays listed and is not registered, neither by Register nor by a scan; a file the built-in rules recognise is excluded from registration this way, while `layout.skip` still hides a file entirely; the outputs of a run belong to the run import, which a rule does not stop). A declaration field a role does not take is refused. Nothing has a default: the example `vda/*/vgt/psi_*.fits` needs its angle unit stated.
- **First match wins**; the order is editable and is the priority. Files matched by several rules are listed as conflicts with the winner and whether the rules would say different things.
- Rules see only what the walk listed: never-read names (`*DO_NOT_OPEN*`, `blind*key*`), skipped folders, links, archives and run records are decided before any rule (tested with a counting filesystem and the pattern `.*`). Rules cannot create runs: run records are found by the built-in rules only.
- **Live preview.** The draft list is sent with the preview request and matched on the server against the cached walk (one matcher; JavaScript regular expressions differ from RE2). A rule with a broken pattern matches nothing and says why. Saving refuses invalid rules with every reason.

**Storage.** Rules live in the catalog (`import_rules`, ordered per project, schema 20) and, only after a separate confirmation (`POST .../import/rules/write` with `write: true`; without it 400 and the file is untouched), in `.vesqira/project.toml` as a `[[import.rules]]` section between `# vesqira:import-rules begin/end` markers. Writing replaces only that section; the rest of the file stays byte for byte. `[[import.rules]]` outside the markers are the researcher's own: they are read, and never rewritten (409). On a host the write follows ADR 0039 (a file Vesqira did not write is not replaced; the rules stay in the catalog and the reply says so). When a scan finds rules in the file and the researcher has never saved a list for the project here (`import_lists`; a project opened on another computer) it loads them; otherwise the file is never read back over saved edits, so deleting every rule sticks, and the page says whether the file holds the same rules, offering to remove the section (a confirmed write of the empty list) when it holds others.

**Apply.** `POST .../import/apply` with `confirm: true` registers the files the **saved** rules select, through the existing paths (`registerPath` for FITS, `registerCatalogPath` for a catalog rule whatever the name, `registerRemoteFile` on a host, all on the shared heavy lane), then applies the rule's declarations through the existing setters (`SetUnitDeclaration`, `SetInterpretation`, `ValidateCatalogDeclaration` then `SetCatalogDeclaration`) with author `rule:<name>` (masks: see **Mask role**). At most 200 files per request (`remaining` says how many are left), 150 s.
- A declaration the researcher made (`declaredBy = user`) is never replaced; one by an adapter or an earlier rule may be. A file's own BUNIT always wins over a rule's unit. A reliability companion an adapter paired stays; a rule never pairs one. Catalog columns are validated against the file's columns first.
- Duplicates follow ADR 0053: a file whose content a dataset holds is offered (`duplicate`, with the matches), not registered; "Register separately" is a click that sends the path in `asNew`. On a host there is no offer (ADR 0053 takes no full hash on registration there).
- A file inside a run folder is registered by that run's import; a rule only adds its declarations once it is registered, otherwise the file is skipped with that reason. A point catalog on a host is skipped (ADR 0044).
- The reply names every file registered, declared, offered, skipped (with why) or failed. An application record (`import_applied`: path, rule, size, modification time, outcome) settles a file at that size and time; a changed file, or a failure, is pending again. Applying twice does nothing twice.

**Provenance labels and tiers.** A rule's declaration (unit, orientation, catalog columns, mask) is stored with the tier `declared` (ADR 0055) and the author `rule:<name>`: the researcher wrote and saved the rule and chose what it applies to, so the declaration is theirs, and the author keeps the rule's name. It is never `inferred`: no adapter read the data to propose it, and it has no mapping version (`catalog.TierOf` treats the `rule:` prefix like `user`; `catalog.RuleAuthorPrefix` and `discover.RulePrefix` are one string, kept equal by a test; migration 18 rewrote earlier non-user authors to `inferred`, and no `rule:` row can exist from before it). Everywhere a declaration is labelled it reads "declared by your rule <name>" (figure declaration comparison, the needs list, the viewer's orientation panels, the reviewer-facing board provenance, which says "an import rule of the author's project" without the name). The reviewer-facing tier line says "declared through an import rule the author saved", without the name. An orientation declared by a rule stays in "Needs your input" until the researcher confirms it as their own, like a run import's proposal (its tier is `declared` all the same); a VGT re-import does not replace it.

**Mask role.** A `mask` rule selects mask files (`data/**/*_mask.fits`). Each is registered as an ordinary image dataset (the mask route needs its file registered, and a registered mask file keeps its own identity and duplicates check), then a typed mask is made of the **target dataset** through the mask route's own code (`makeMask`, the code behind `POST /api/datasets/{id}/masks` with method `import`): same grid check (a WCS that cannot confirm the match is recorded as "matched by pixel shape only"), the type, what a nonzero pixel means, the description, the worker, a mask file of its own. The target is named by `maskTarget`, a project-relative path with `{dir}` (the mask file's folder, only at the start) and `{stem}` (its name without extension and without `maskStrip`): `{dir}/{stem}.fits` with strip `_mask` takes `data/psi_mask.fits` to `data/psi.fits`. A name that lacks the strip suffix, a target outside the project and a mask that would be its own target are refused. The mask is `declared`, author `rule:<name>`, named after the file. Refusals leave no mask and say why in the reply: a target that is not registered (reported as `failed`, so a later apply tries again; files of the mask role are applied after the others in one request, so a target registered in the same apply is found), another grid, a point catalog, a host (a mask is made on this computer from files read here) or masks not being configured. Applying again does not make a second mask: one by the same rule with the same name is reported as already imported (delete it to import the file again; a changed file is a new application record, not a replacement). `missing` is not a type a rule may declare: pixels with no value are computed from the data. The mask file stays registered as a dataset in the catalog and is never deleted or unregistered by this.
- **Mask files in the explorer (amendment).** `makeMask` records the id of the registered file an import was made from in the mask's rule (`sourceDatasetId`; no schema change: the rule is JSON). `GET /api/datasets` marks a dataset `maskSourceFor: [{id, name}]` when it is the source of an imported mask and nothing else uses it (`lifecycle.MaskSources`, derived from the rows on every request: no figure, saved region, exploration step, run output, analysis input or result, orientation or reliability declaration, mask of its own, or offline copy; no file names are read). The explorer hides those by default with a count and a Show toggle, and never hides the open dataset; the target's Masks section says "Mask file: <name>, a mask source for <dataset>" (`Mask.sourceDataset`). Forgetting the mask, or using the file for anything else, makes it an ordinary dataset again. Masks made before the id was recorded do not say which file they came from (the rule holds only a base name), so their files stay listed: not guessed.

**Rescans.** Every scan counts what the saved rules select (`importRules` in the project summary: rules, matched, pending, new). "N new files match your rules" is the pending files no earlier scan counted (a `pending` application record remembers them); the explorer links to the page. **A scan never registers a file for a rule and never applies a declaration**; registration of what rules select happens only on the Register click. (The scan still registers FITS files by the built-in rules, as before.)

**Contracts.** The five routes are in `bodies.json` (no growth of `undescribed.txt`); a contract test validates their replies against the spec.

**Schema.** Version 20 adds `import_rules`, `import_lists` (one row once a list was saved, even an empty one) and `import_applied` (DDL shared by the migration and `projects.Open`). **Numbering:** 18 is typed masks and tiers (ADR 0055) and 19 the exploration history (ADR 0057); the snapshot is `testdata/schema_v20.sql`.

## Alternatives

- **Register what rules select during every scan.** One less click, and a stray pattern would register and declare files unseen. Rejected: the scan counts, the researcher confirms.
- **Match drafts in the browser.** Instant, but a second glob and regex implementation that drifts from the server's (JavaScript regex is not RE2). Rejected; a short debounce and the cached walk keep it fast.
- **Rewrite project.toml from the catalog on every save, or append superseding blocks.** The first loses the researcher's edits to the file, the second cannot express reordering. A marked section Vesqira owns, replaced only on confirmation, avoids both.
- **A mask rule that inherits the target from a registered neighbour by size.** Guessing which dataset a mask belongs to from shape would be a silent assumption (invariant 3); the rule states the path relationship instead.
- **Tier `inferred` for a rule's declaration.** It would make the researcher's own rule look like an adapter's guess, and the needs list and reviewer text would then misstate who decided. Rejected: `declared`, author `rule:<name>`.
- **Defaults for the angle unit or the coordinate frame.** The example rule from the roadmap has none; filling it in is exactly the silent guess invariant 1 forbids.

## Consequences

- Researchers can describe a folder's conventions once and re-apply them; declarations stay labelled as theirs and are never promoted to the file's.
- Every scan stats each unrecognised file (up to 50 000) for the inventory.
- A scan on a host lists the whole project (the worker's walk has no subtree option); the folder only narrows what is classified.
- `internal/projects` now imports `internal/schema` (architecture table updated).

## Validation

Table tests for glob and regex matching, validation, first match and conflicts, grouping, built-in roles per run kind, depth and entry bounds, the never-read and archive exclusions (counting filesystem), and the project.toml section (bytes kept, foreign rules refused, quoting round trip); server tests for a read-only preview, live draft preview, save refusal, apply with provenance, the researcher's declaration and a file's BUNIT winning, duplicates offered and registered separately, run files, the confirmed write, rescan counts and "a scan never registers", a catalog rule with the real worker, a host folder through the fake host harness, and a contract test; a migration test from schema 17; a mask rule applied with the real worker (declared mask authored by the rule, the right pixel count, the dataset's file unchanged, an unregistered target retried, another grid refused, applying twice making one mask), the mask target template (refusals, `{dir}` at the root) and the rule's validation and project.toml round trip, `TierOf` for a rule author; web tests for the rule editor (including the mask fields), the preview, conflicts, save and write confirmation, and apply with duplicates.

## Rollback / Migration

Three new tables, no change to existing ones (the mask role adds no table: its masks are rows of ADR 0055's `masks`). To roll back, drop `import_rules`, `import_lists` and `import_applied` and set `user_version` back; declarations already applied stay (each is labelled `rule:<name>` and can be withdrawn like any declaration). `[[import.rules]]` sections stay in researchers' project files and are inert to older programs.
