# ADR 0029: Terminal, editor and VPN inside the app

Status: **accepted**; editor for local files (step 1, `--enable-editor`), the integrated terminal (step 2, `--enable-terminal`) and the VPN companion (step 3, `--enable-vpn`) implemented; host files in the editor not built. Owner decision 2026-11-05: owner-only, off by default; built in the order editor, terminal, VPN.

## Context
The owner wants a researcher never to leave the app: edit a pipeline config or Julia file, run a command, bring the cluster VPN up. The interview decided an integrated editor with external IDE hand-off (Q39) and named Monaco and xterm.js for the desktop shell (Q148); an integrated terminal appears in the workspace panels (Q9). No VPN client appears anywhere in the interview; the host form today tells the user to bring the VPN up themselves (for example `gpclient`).

Three things are different from everything built so far, and they share one risk. The app reads files and runs fixed, validated operations. A terminal runs any command as the user, an editor writes files, and a VPN client changes the machine's network. A web page that can reach the local API must never be able to do those things by accident, by a malicious site, or from the review listener.

## Options

**A. Terminal and editor as owner-only, off by default; VPN as a button that runs the user's own client (recommended).**

*Terminal.* A pseudo-terminal on the machine running Vesqira, shown with xterm.js. Local: the user's shell. Remote: `ssh -tt <host alias>` with the same ssh and agent the app already uses. Off unless the server is started with `--enable-terminal` (a setting turned on in the app that restarts the listener was considered and is **not built**; the flag is the only switch). Only on the loopback owner listener, never on the review listener. The connection is a WebSocket that must pass the same Host and Sec-Fetch-Site checks as the API, a per-session random token carried in the WebSocket subprotocol (not the URL), and an `Origin` equal to the page's. One session per tab, closed with the tab; an idle limit. The audit log records that a session opened and closed (host, time), never keystrokes or output.

*Editor.* Monaco for text files the app already knows how to name: pipeline configs (TOML), job scripts, Julia and Python sources, Markdown notes. A file is editable only inside a registered source root (the same canonicalising check as reading) or a host's declared roots; saves are atomic (write a temp file, rename), refuse when the file changed since it was opened (compare size and modification time, show the two versions, never overwrite silently: Q38), and are recorded in the audit log with a hash before and after. FITS and other binary files are never opened as text. Language servers and Git operations are later (Q39).

*VPN.* Vesqira does not implement a VPN. A host can carry an optional "connect command" the user sets once (for example `gpclient connect vpn.example.edu`) and a "reachable check" (the existing host check). The app shows "VPN: not reachable" with a Connect button that runs that command; because such clients need privileges, the command is run through `pkexec` or the user's own polkit rule and the app never sees a password or token (the client or polkit asks in its own window). Output is shown, the result is verified by the host check, and nothing is stored beyond the command.

- Keeps the single-user trust model: everything is the owner's own account on the owner's machine.
- Each piece is optional and separately switchable; with all off the app is as safe as today.
- Costs: a WebSocket and PTY layer in Go, a Monaco bundle (large; load it only when a file is opened), polkit handling that differs per distribution.

**B. Hand off to external programs (a "Open in terminal / editor / VPN app" button).** Smallest and safest; does not meet the goal of not leaving the app.

**C. A shared hosted terminal and editor (a web IDE service).** Needs accounts and sandboxing (ADR 0028 option B); out of proportion for one researcher.

## Recommendation
Do A in three independent steps, each behind its own switch, in this order: editor (lowest risk: confined to roots, atomic and audited saves), terminal (needs the WebSocket guards), VPN button (small, but privileged). Keep B available throughout as the fallback when a piece is off.

## What A would add (if approved)
- `GET/PUT /api/files/text` for the editor with the root check, optimistic concurrency and audit; `GET /api/terminal` (WebSocket) with the guards above; host fields `vpnCommand` and a `POST /api/hosts/{id}/vpn` that runs it.
- Layering tests: the review package must still reach nothing but the snapshot store (`internal/arch`), and a test that the terminal and editor routes are not mounted on the review listener.
- A section in SECURITY.md describing what each switch enables.

## Validation (when built)
Cross-site and cross-origin WebSocket attempts, a missing or wrong token, and a request on the review listener are refused; a save over a changed file is refused with both versions shown; a path outside the roots or through a symlink is refused; the audit log shows opens, closes and saves without contents; the VPN command is stored verbatim, run without a shell, and never receives anything from the page except "run".

## Implementation notes: editor, step 1 (local files only)
- **Switch.** `--enable-editor` sets `Server.EditorEnabled`; the routes are registered only then (off: 404) and `GET /api/capabilities` reports `features.editor`. The web app shows the entry point only when that is true; a failed capabilities request counts as off.
- **Where.** Routes live in `internal/server`, the owner listener. The review handler is a different package that `internal/arch` already forbids from reaching the server package; `TestEditorRoutesAreNotOnTheReviewListener` sends GET, PUT, POST and DELETE to it.
- **Authorisation.** The path goes through `s.roots().Resolve`, the check that gates reading (symlinks resolved first, containment by `filepath.Rel`, regular file only; opened project folders count as roots). Everything after that uses the resolved path. Also refused: credential folders (`holdsCredentials`, as the file tree), extensions outside the text allowlist (toml, yaml, yml, json, jl, py, sh, slurm, sbatch, md, txt, cfg, ini, conf, log; no extension is allowed), FITS by extension and by `SIMPLE  =`, NUL bytes, invalid UTF-8, and files over 2 MiB. Also refused (403, open and save): files under `data/raw` or `data/external` of the root that holds them, by `discover.RoleOf`, the rule the scanner uses for the explorer's `readOnly` flag. The `PUT` body is checked with `utf8.Valid` before JSON decoding (the decoder would otherwise turn invalid bytes into U+FFFD and write them). A save never creates a file.
- **Concurrency.** `GET` returns content, size, `mtime` (nanoseconds as a decimal string, since a JSON number loses digits in a browser) and the SHA-256. `PUT` must send those three as `base`; if any differs from the file on disk it answers 409 with the current file and writes nothing. "Keep mine" in the UI resends with the base the conflict returned, after an explicit confirmation. One save at a time per process; another program writing in the instant between comparison and rename is not excluded (the rename itself is atomic).
- **Atomic save.** Done through an `os.Root` opened on the root that holds the file (`sourceroot.Roots.Under`), so a folder swapped for a symbolic link after the check cannot send the write outside it: temporary file created there (random name, `O_EXCL`, 0600), permission bits copied from the original, fsync, `Root.Rename`, fsync of the folder (`writeFileAtomic`, shared with the project file writer, whose root is the project folder). Owner, ACLs and extended attributes are not carried over; a read-only folder fails the save.
- **Audit.** `file saved`, kind `file`, detail `sha256 <before> -> <after> <path>` (hashes first because the detail is cut at 300 characters). `file opened for editing`, kind `file`, detail `sha256 <hash> <path>`, is recorded for each successful open. Never contents; refused opens and refused saves are not recorded.
- **Writes are guarded like the other mutating routes**, plus: `PUT` now requires `application/json` (the check covered POST only), and any non-GET request carrying an `Origin` that differs from `Host` is refused. Through the Vite dev and preview servers this holds only because `apps/web/vite.config.ts` sets `changeOrigin: false` on both proxies (the short proxy form rewrites `Host` and every write would be refused); `TestLocalOnlyOriginMustEqualHost` documents the rule and `make e2e` exercises it.
- **Text the editor surface cannot show.** A UTF-8 byte order mark is set aside on open and written back first on save. A file with a bare CR (not part of CRLF) is not opened, with a message, because the editor would save its line breaks as LF.
- **Not yet:** host files (a later slice, with the host's declared roots), language servers. The editor screen is a first version that has not been through a design review.
- **Validation done:** Go tests for outside root, sibling prefix, `..`, symlink escape (file and folder), credential folder, binary, FITS (extension, magic, symlinked), oversize, unknown extension, stale base (409 with current content), keep-mine resend, removed file, mode preserved, audit without content, cross-site and foreign Host and Origin, switch off, review listener, and the responses against the OpenAPI spec; symlinked-folder swap during a save, raw and external data refused, invalid UTF-8 body refused, opens audited; web tests for the conflict flow, the byte order mark and bare CR.

## Implementation notes: terminal, step 2
- **Switch.** `--enable-terminal` sets `Server.TerminalEnabled`; `POST /api/terminal/sessions` and `GET /api/terminal` are registered only then (off: 404) and `GET /api/capabilities` reports `features.terminal`. Owner listener only: the review handler is a different package that `internal/arch` keeps away from the server package, and `TestTerminalRoutesAreNotOnTheReviewListener` (review package) sends the session request and a WebSocket upgrade to it. Not available in multi-user mode (ADR 0050 lists the terminal with the editor as unavailable there; that mode does not exist yet, so nothing refuses the flag today).
- **Dependencies.** `github.com/gorilla/websocket` v1.5.3 (BSD-2-Clause): no WebSocket library was in `go.mod`; it is the long-established one, supports subprotocol negotiation, read limits and ping/pong, and has no dependencies of its own. `golang.org/x/net/websocket` was rejected (frozen, no read-limit or subprotocol control worth the name). `github.com/creack/pty` v1.1.24 (MIT): allocates the pseudo-terminal and makes the child a session leader with the terminal as its controlling terminal; the alternative is hand-written `ioctl`s for `/dev/ptmx`, which is the thing a small vetted library is for. Web: `@xterm/xterm` and `@xterm/addon-fit` (MIT), loaded only when the Terminal screen opens (a separate chunk, like Monaco). Both Go modules are covered by the vendored-sources build (`go mod vendor`, ADR 0052).
- **What runs.** Local: `$SHELL -l` (an absolute, executable path, else `/bin/sh`) in the user's home, with `TERM=xterm-256color`. Host: the stored, validated destination of the host chosen **by id** (`hosts.Manager.TerminalCommand`): the same ssh binary, `ControlPath` socket and environment (so the user's agent) as the worker connections, plus `-tt`, `ServerAliveInterval` and no `BatchMode`, so a passphrase or one-time-code prompt appears in the terminal; Vesqira never sees it. The page cannot name a command, a binary or a destination.
- **Guards, all on the server.** (1) `localOnly` for the POST and for the upgrade: loopback `Host`, `Sec-Fetch-Site` same-origin or none, JSON content type for the POST. (2) The upgrade must carry an `Origin` equal to the page's own scheme and host (`sameOrigin`); a missing one is refused too, since every browser sends it on a WebSocket handshake. (3) A query string of any kind is refused (400), so a token can not be passed, or logged, in the URL. (4) The token is 32 random bytes from `POST /api/terminal/sessions`, returned once, held only as its SHA-256, valid 60 s, consumed by the first connection attempt that presents it whether or not the rest succeeds, and offered as the subprotocol `vesqira-token.<hex>` next to `vesqira.terminal.v1`; the server selects the latter and never echoes the former. Anything else among the offered subprotocols refuses the request. (5) One session per tab: the page sends a per-page-load tab id and a new session for it ends the old one (and voids its unused token); at most 8 sessions run at once and 32 tokens wait. The server cannot tell two browsers' tabs apart beyond that id; the page closes its socket on `pagehide`.
- **Limits.** Input frames at most 64 KiB (the library closes with 1009 beyond that); output frames at most 32 KiB; control frames at most 256 bytes; the only control message from the page is `resize` with columns 1 to 500 and rows 1 to 200, and anything else (unknown type, out of range, not JSON) ends the session. Idle: no *input* for 30 minutes (output does not count, so a forgotten `tail -f` does not keep it alive); lifetime 8 hours; a ping every 20 s with a 60 s read deadline, so a vanished page ends the session. On end the shell gets SIGHUP, then SIGKILL to its process group after 2 s; the server tells the page why in a final `{"type":"exit","reason","code"}` message.
- **Audit.** `terminal session opened` and `terminal session closed`, kind `terminal`, target the host id (0 for this computer), detail `this computer` or `host <name>` and, on close, the duration and the reason. Never input or output (`TestTerminalAuditHasNoContent`).
- **Web.** A Terminal button in the rail (hidden when the capability is off or unreachable) opens a full-screen screen with a "Where" choice (this computer or a host from the hosts list), an explicit "Open session", and for an ended or refused session a visible reason and "New session": nothing reconnects by itself. Colours come from the design tokens (light and dark, re-read when the theme changes). Esc and Tab go to the shell, so the dialog does not close on Esc (`Modal` got `keepEscape`); Ctrl+Shift+M moves focus to Close, Ctrl+Shift+C and Ctrl+Shift+V copy and paste, and Copy and Paste buttons do the same. Closing a live session asks first. The Vite dev and preview proxies carry `ws: true` (and still `changeOrigin: false`, which the Origin rule needs).
- **Known limits.** The screen is a first version that has not been through a design review. ANSI colours follow the tokens, so programs that assume the usual palette may be less distinct than in a dedicated terminal. A local shell sees Vesqira's own environment. ssh options come from the user's ssh configuration, not from the app. Closing the screen ends the session (no detached sessions). The single-user trust model is unchanged: the terminal is the owner's own account.
- **Validation done:** Go tests for off by default (404, capability false), review listener, missing, wrong, short, doubled, reused, expired and superseded tokens, a token in the URL, foreign `Origin` (cross-site, other port, with a path, `null`, missing), foreign `Host`, cross-site `Sec-Fetch-Site`, a shell that echoes input and reports its exit code, resize applied and bounded, frame bounds, idle and lifetime endings, one session per tab and a cap on sessions, a closed page ending the shell, audit without content, a host session through a fake ssh (arguments, agent socket, no `BatchMode`), host chosen by id only; web tests for the screen's states against a stand-in terminal; one end-to-end smoke test through the preview proxy.

## Rollback
All routes are additive and off by default; remove the flags and the routes disappear.

## Implementation notes: who may connect to the owner listener
- **Guarantees, exactly.** Browser pages are blocked by `Host`, `Sec-Fetch-Site`, `Origin` and (terminal) the one-time token. Other local user accounts are blocked on Linux by a peer-uid gate (below). Processes of the same account are trusted: that is the single-user model, and the terminal gives them nothing they do not already have. macOS and Windows have no gate: any local account reaches the owner API there.
- **Gate (`internal/server/peergate.go`).** The owner listener is wrapped in a `net.Listener` that, per accepted connection, finds the row of `/proc/net/tcp` or `tcp6` whose local address is the peer's address and port and whose remote address is ours, and reads its uid column. A different uid, a lookup error, a missing row or an unreadable table closes the connection before any HTTP (fail closed). Addresses are parsed per 32-bit word in the machine's byte order, IPv4-mapped forms are unmapped, input is bounded (16 MiB per table, 512 bytes per line). The socket table is the kernel's record of the creating uid, so the peer cannot influence it. Refusals are counted and logged (at most one line per 10 s, no addresses).
- **Switches.** `--allow-other-local-users` turns the gate off (dangerous; logged at start). Without it, on Linux the server refuses to start if `/proc/net/tcp` is unreadable; on other platforms it warns, and refuses `--enable-terminal` and `--enable-editor`.
- **Alternatives rejected.** A bearer token for the owner API (every client, including the agent CLI and the desktop shell, would have to carry a secret; a same-uid process can read it anyway); a unix socket (browsers cannot reach it, so the web app would need a proxy); `SO_PEERCRED` (unix sockets only).
- **Not gated:** the review listener and the publish server.
- **Session end.** Closing a session sends SIGHUP and then, after 2 s, SIGKILL to the shell's process group and to every process whose session id is the shell's pid (`/proc/*/stat`, bounded), also when the shell exited by itself, so a job in its own group or one that ignores SIGHUP does not outlive the tab. A process that calls `setsid` leaves the session and is not tracked. Where `/proc` is missing only the process group is signalled.
- **ssh terminal.** The argument list ends with `-e none` (no escape character is interpreted from page input) and `--` before the destination. The terminal uses the same `ControlPath` as the workers, so a master opened interactively (for example after a one-time-code login) is reused by the `BatchMode` workers and vice versa. Both the local shell and ssh run with the full environment of the user running Vesqira (ssh sends what `SendEnv` allows).

## Implementation notes: VPN companion, step 3
- **Switch.** `--enable-vpn` sets `Server.VPNEnabled`. `POST /api/hosts/{id}/vpn` and `POST /api/hosts/{id}/vpn-config` are registered only then (off: 404), a host created with a command is refused with 403, and `GET /api/capabilities` reports `features.vpn` (the page shows nothing about a VPN otherwise). The task text said "off unless the host has a command"; the flag is added because a stored command is a program the app runs as the user, so setting one is as powerful as the terminal and this ADR asked for a switch per step. On macOS and Windows the flag, like the other two, needs `--allow-other-local-users`. Owner listener only: `TestVPNRoutesAreNotOnTheReviewListener` (review package).
- **What is stored.** `hosts.vpn_command` and `hosts.vpn_disconnect` (schema 16 in this branch; numbered again when branches merge), each the JSON array text of the argv, or empty. `hosts.ValidateVPNArgv`: the first part an absolute clean path or a bare name (`[A-Za-z0-9_+][A-Za-z0-9._+-]*`, resolved through `PATH` by `exec` when it runs), at most 16 parts, 512 bytes each, 2048 in all, no NUL, line breaks or invalid UTF-8; a JSON body with a non-string element, an object or an unknown field is a 400. Stored verbatim: no trimming, splitting or quoting rules.
- **Running it.** `hosts.RunVPN`: `exec.CommandContext` with the stored argv, no shell, no stdin, the user's environment, its own process group so the timeout (two minutes, `Server.VPNTimeout` in tests) kills everything it started, stdout and stderr into one bounded buffer (16 KiB; the rest is dropped as it arrives), ANSI and other control sequences removed. A request that closes does not stop a half-finished connect (the time limit does). One run at a time per host (409 for either direction while one runs). The page sends only `{"action":"connect"|"disconnect"}`; the body is decoded strictly. Afterwards the host's worker is dropped (`Manager.Forget`, so no stale ssh path survives a network change) and the host check runs; the answer is "VPN command finished; the host is reachable" or "... still not reachable" (also for a non-zero exit, a timeout, and a program that did not start).
- **Reachability and the job watcher.** `Server.reach` remembers, in memory, whether each host last answered (host check, watcher, VPN recheck); `GET /api/hosts` returns `reachable` (`yes`, `no`, `unknown`) and `reachableAt`. A connect that exits 0 and leaves the host reachable marks the host so the watcher asks it at once and forgets its backoff (the watcher loop is also woken instead of waiting for its 15 s tick).
- **Audit.** `host vpn connect` or `host vpn disconnect`, kind `host`, detail `<host>: exit N|timed out|did not start after M ms`; `host vpn commands` when they are changed (set or cleared, not the text). Never the command or its output.
- **Limits to know.** A client that stays in the foreground while the tunnel is up (some `gpclient connect` setups) is stopped at the time limit, which drops the tunnel: use the client's background option or a wrapper. Programs that need a terminal (a password prompt on a tty) do not work: there is no tty and no stdin; use `pkexec` or a polkit rule. The command can still be changed by anything that reaches the owner API with the flag on (same trust as the terminal).
- **Validation done:** Go tests for the argv validator (empty, oversized, too many, non-strings, relative, NUL, shell text), verbatim storage, a fake program that prints its argv (a `;`, `$HOME` and a backtick arrive as text and nothing is created), extra body fields and wrong actions refused without running anything, timeout kills the process tree, one run per host, audit without output or command, reachability recheck counted, watcher retry after a kick, review listener, feature off, schema migration; web tests for the button states, the stored command shown verbatim, only the action sent, and JSON parsing of the form fields. Not run against a real VPN client or a real polkit prompt.
